# 文档A：项目方案书（V6.0）

**文档定位：** 回答"为什么做、做什么、做到什么程度"，用于立项决策与团队对齐。

***

## 一、项目背景与市场机会

### 1.1 行业痛点

| 用户群体       | 核心痛点                        | 现有方案不足       |
| :--------- | :-------------------------- | :----------- |
| **中小微企业**  | 老板看不懂财务数据，财务软件成了"为报税而记账"的工具 | 操作门槛高，经营分析缺失 |
| **代理记账公司** | 客户量大客单价低，利润依赖人工效率           | 手工录入瓶颈，出错率高  |

传统财务软件的底层逻辑是"让会计更快地录入凭证"，而非"让生意人看懂经营"。AI大模型技术的成熟，为重构范式提供了可能。

### 1.2 核心机遇

- **IM生态渗透率高**：微信/企业微信/飞书覆盖绝大部分中小企业主的日常沟通
- **AI能力成熟**：OCR识别、自然语言理解、Text-to-SQL等技术进入可商用阶段
- **代账行业人力成本攀升**：亟需自动化工具替代重复劳动

***

## 二、项目愿景与产品定位

### 2.1 项目愿景

> **打造一款兼顾传统Web与AI智能交互的财务软件，让专业会计高效工作，让老板像聊天一样看懂生意。**

通过"双接口"架构，Web端为会计和财务经理提供完整的专业操作界面，IM端为老板和管理者提供"对话即服务"的智能体验。两者共享同一套业务中台，确保数据一致、逻辑统一。

### 2.2 产品定位

| 维度       | 第一阶段（Web端专业财务软件）    | 终极定位                        |
| :------- | :------------------------ | :-------------------------- |
| **产品形态** | Web端完整财务软件（传统操作模式）   | Web端专业工具 + IM端AI智能助手 + 移动H5 |
| **核心用户** | 5-10家种子企业（会计、财务经理为主） | 中小微企业 + 代理记账公司              |
| **核心价值** | 验证业务逻辑闭环，积累真实用户反馈      | 从记账到经营决策、代账协同的全链路覆盖         |
| **接入方式** | 传统Web（浏览器访问）            | 传统Web + Hermes AI（IM对话）     |

### 2.3 战略路线

```
第一阶段（进行中）                    第二阶段（重点）                    第三阶段
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────┐

│ · 完整业务逻辑闭环      │    │ · Hermes Agent       │    │ · 进销存+财务   │
│ · 核心模块全部落地      │    │ · 自然语言交互          │    │ · 金税直连     │
```

### 4.1 双接口体系（架构蓝图）

### 4.2 第一阶段：Web端专业财务软件（已完成）

第一阶段优先完成传统Web端，原因如下：

1. **Web端是完整财务软件的基石**，所有业务逻辑在此落地，API 设计需在此阶段稳定
2. **会计与财务经理习惯 Web 操作**，批量导入、审核工作台、核销界面等需要大屏高效交互
3. **先跑通业务闭环**，积累真实数据，再引入 AI 增强更稳健
4. **业务 API 在 Web 端实践中逐步稳定**，为后续 Hermes 调用打下坚实基础

### 4.3 七大流程模块（主骨架）

```
数据采集（单据导入） → 智能处理（审核与过账） → 期末处理（自动计提与结转）
        ↓
  税务合规（智能税务管理，贯穿全流程）
        ↓
  结果输出（财务报表生成，数据层）
        ↓
  智能查询与汇总（灵活探索，数据中枢）
        ↓
  决策支持（经营分析与推送，洞察层）
```

### 4.4 模块一：数据采集入口

| 采集方式     | Web端（第一阶段已实现）         | IM端（第二阶段重点）      |
| :------- | :------------------------- | :------------------ |
| **发票**   | Excel批量导入（两遍处理引擎）、手工录入 | 拍照/文件发送、微信卡片转发    |
| **银行流水** | Excel/CSV文件导入、手工录入     | 文件拖入、手机截图识别       |
| **语音记账** | 不适用                       | 语音转文字，提取金额用途      |
| **批量处理** | 压缩包上传、批量导入              | 压缩包发送，Agent自动解压处理 |

### 4.5 模块二：智能处理与审核链

**审核链设计（第一阶段已实现）：**

| 步骤    | 角色      | 操作                            |
| :---- | :------ | :---------------------------- |
| 1. 制单 | 会计      | 手工录入或导入生成凭证草稿，提交至"待审核"      |
| 2. 审核 | 财务经理    | 登录审核工作台，分屏查看原始单据与凭证，可修改、通过或驳回 |
| 3. 过账 | 财务经理/会计 | 已审核凭证执行过账，写入正式账套              |

**关键规则：**

- 所有审核操作记录完整日志，明确记录审核人
- 财务经理拥有冲红账、反审核、反结账等高级权限
- 所有操作记录不可篡改的操作日志

**第二阶段增强（AI辅助，V2规划）：**

> 详细需求见 `docs/02-需求分析/需求分析书.md §十二、远期规划（AI增强）`

- **AI 科目推荐**：根据摘要自动推荐会计科目（覆盖手工凭证录入、单据生成凭证、银行流水生成凭证三大场景）
- **AI 凭证草稿**：自然语言描述自动生成完整凭证（多行借贷分录）
- **智能异常检测**：自动识别异常分录并提示
- **实现路径**：V1 确定性规则 → V2.1 规则增强（中文分词） → V2.2 AI 辅助推荐 → V2.3 AI 全自动推荐

### 4.9 模块六：智能查询与汇总中心

**定位：** 连接基础核算与决策支持的数据中枢。提供凭证明细查询、辅助余额表、账龄分析等灵活查询能力。

| 交互端         | 实现方式                                                    | 查询特点                        | 实现阶段 |
| :---------- | :------------------------------------------------------ | :-------------------------- | :--- |
| **Web端**    | 用户在表单中选择精确条件，前端直接拼装API参数                                | 精确查询：所有条件都是确定的              | ✅ 已实现 |
| **IM端（AI）** | 用户用自然语言提问，Hermes Agent通过Skills将模糊表达解析为精确的API参数，再调用后端API | 模糊转精确：用户感觉是模糊查询，但后端始终收到精确参数 | 第二阶段 |

**核心原则：**

- **后端API只做精确执行**：所有查询参数都是确定性的，不做任何语义理解或模糊匹配
- **Hermes Agent负责智能翻译**：将自然语言解析为精确API参数
- **Skills逐步积累**：前期预置基础Skills，中期通过自学习优化解析准确率

### 4.10 模块七：决策支持（第二阶段重点）

洞察层，帮老板看懂生意：

- **经营驾驶舱**：核心指标可视化（收入、利润、现金流、税负率）
- **自然语言问答**：老板可以用日常语言提问"这个月利润怎么样""应收账款有多少"
- **智能预警推送**：通过IM主动推送异常预警（现金流紧张、税负率偏高、大额支出）
- **经营建议生成**：AI根据财务数据生成经营建议

## 七、关键设计原则

### 7.1 安全第一

1. 安全一票否决：任何功能未通过安全审查不得上线
2. 默认最小权限：新服务/新用户默认最低必要权限
3. 纵深防御：传输加密→存储加密→审计追踪层层设防
4. 安全左移：需求阶段开始嵌入安全设计

### 7.2 双接口统一中台

- Web端与IM端共享同一套业务API，确保数据与逻辑一致
- 业务服务不做AI判断，只执行确定性操作
- Hermes Agent负责智能翻译，将多模态输入转化为标准API调用
- 第一阶段先建Web，第二阶段加AI，渐进式演进

### 7.3 审核分离与人工最终审核权

- 会计负责制单，财务经理负责审核
- 所有操作必须经人工确认才能生效
- 财务经理拥有冲红账、反审核、反记账、反结账等完整撤销权
- 所有操作记录不可篡改的操作日志

### 7.4 零小程序依赖

- 不开发独立微信小程序
- 移动端轻量查看通过IM内置浏览器或H5实现
