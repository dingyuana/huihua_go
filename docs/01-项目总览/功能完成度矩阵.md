## 月末结账前置条件完整性评估

```
结账前必须满足（当前实现）：
  ✅ 全部凭证已过账（强校验，阻断）
  ✅ 资产负债表平衡（强校验，阻断）
  ✅ 损益已结转（强校验，阻断）
  ⚠️ 折旧已计提（检查函数存在，但未接入close_period_core）
  ⚠️ 银行已对账（有检查，但默认值True绕过；且is_reconciled bug使结果不可信）

结论：结账本身可以跑，但前置条件检测不完整。
      最大风险：is_reconciled=True bug + 折旧检测缺失
```

## 与月末结转的关系

**结转依赖的核心前提（当前）：**
1. ✅ 凭证过账 → close_period_core强校验
2. ✅ 报表平衡 → _check_report_balance强校验
3. ✅ 损益结转 → has_profit_loss_entry强校验
4. ⚠️ 折旧计提 → _check_depreciation_detail有但未接入
5. ⚠️ 银行对账 → bank_reconciled检查存在但因bug绕过

**结转不依赖（可以后做）：**
- 智能分类引擎（P1-2）
- 发票核销联动（P1-4）
- 凭证模板（P2-6）

但如果往来余额不更新（核销缺失），**结账后的资产负债表中的应收应付科目余额会不准确**。这是数据质量问题，不是流程阻塞问题。
