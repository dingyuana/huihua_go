# 文档A：项目方案书（V6.1 Web端MVP · 零AI）

**产品代号**：轻账目\
**核心价值**：手工记账，自动归类，一眼看清钱都花哪了、赚了多少。\
**目标用户画像**：10人以下的微型企业、个体户老板，无专职会计，自己管钱管票。\
**MVP原则**：纯Web端，手工录入，规则自动分类，零AI依赖。

***

## 一、项目背景与市场机会

### 1.1 行业痛点

| 用户群体         | 核心痛点                | 现有方案不足       |
| :----------- | :------------------ | :----------- |
| **微型企业/个体户** | 老板自己管钱，记账繁琐，传统软件太复杂 | 需要会计知识，操作门槛高 |

“轻账目”的底层逻辑是：**让老板不用学会计，手工录入几笔收支，系统自动归类，一眼看懂经营状况。**

### 1.2 核心机遇

- Web端无需安装，浏览器即开即用
- 规则引擎技术成熟，可自动匹配科目
- 微型企业老板数量庞大，市场空白明显

***

## 二、项目愿景与产品定位

### 2.1 项目愿景

> **手工记一笔，自动归好类；看一眼图表，看懂生意。**

打造一款“无会计术语、无复杂操作、无AI依赖”的纯Web端微型企业记账工具。老板只需在电脑上简单录入收支，系统自动分类，通过图表直观展示经营状况。

### 2.2 产品定位

| 维度       | MVP阶段              | 后续演进          |
| :------- | :----------------- | :------------ |
| **产品形态** | 纯Web端（浏览器访问）       | 可扩展移动端、AI智能录入 |
| **核心用户** | 微型企业老板、个体户（单人使用）   | 可扩展至代账会计      |
| **核心价值** | 手工记账 + 自动归类 + 简易看板 | 完整财务+税务+AI    |
| **交互方式** | Web表单 + 列表 + 图表    | 可扩展IM/AI交互    |
| **AI依赖** | **零AI**，全部基于规则引擎   | 后续引入OCR、NLP   |

***

## 三、目标客户与市场策略

### 3.1 客户画像

| 特征       | 描述                |
| :------- | :---------------- |
| **企业规模** | 10人以下，年营收500万以下   |
| **决策者**  | 老板本人，无专职会计        |
| **痛点**   | 自己管钱管票，记账繁琐，看不懂账  |
| **使用习惯** | 日常在电脑前办公，可通过浏览器操作 |
| **付费意愿** | 基础功能免费，高级功能可付费    |

### 3.2 市场策略

- **SEO/搜索获客**：通过“免费记账”“个体户记账”等关键词获取用户
- **口碑传播**：老板之间的推荐
- **免费增值**：基础记账免费，高级分析/导出付费

### 4.2 模块一：收支录入（手工录入）

| 功能         | 说明                           | 优先级 |
| :--------- | :--------------------------- | :-- |
| **录入一笔支出** | 表单：日期、金额、支出类别（下拉选择）、摘要（手工填写） | P0  |
| **录入一笔收入** | 表单：日期、金额、收入来源、摘要             | P0  |
| **收支列表**   | 按时间倒序展示所有记录，支持编辑和删除          | P0  |
| **发票信息抄录** | 老板拿到纸质发票，手工将金额、类别、摘要录入系统     | P0  |
| **不做**     | 无发票拍照OCR，无二维码扫描，无文件导入，无AI识别  | —   |

### 4.3 模块二：自动归类（规则引擎）

| 功能           | 说明                                | 优先级 |
| :----------- | :-------------------------------- | :-- |
| **支出类别自动匹配** | 根据摘要关键词自动推荐类别（如填“请客吃饭”自动选“业务招待费”） | P0  |
| **类别别名**     | 允许老板将“业务招待费”改成“请客吃饭”，看板中显示别名      | P0  |
| **手工调整类别**   | 若自动匹配不准，老板可手动更改类别                 | P0  |
| **不做**       | 无AI模型，无机器学习，全部基于关键词规则             | —   |

**规则引擎示例（支出类）：**

| 摘要包含关键词     | 自动分类  | 默认别名 |
| :---------- | :---- | :--- |
| 吃饭/请客/餐厅/餐饮 | 业务招待费 | 请客吃饭 |
| 加油/汽油/油费    | 交通费   | 加油出行 |
| 电脑/手机/设备    | 固定资产  | 设备采购 |
| 办公/文具/打印    | 办公费   | 办公用品 |
| 房租/物业       | 租赁费   | 房租   |
| 快递/物流/运输    | 运输费   | 快递物流 |
| 其他未匹配       | 其他支出  | 其他   |

### 4.4 模块三：老板看板（图表呈现）

| 功能         | 说明                         | 优先级 |
| :--------- | :------------------------- | :-- |
| **本月收支概览** | 大字体显示本月收入、支出、结余            | P0  |
| **月度趋势图**  | 近6个月收入/支出/结余折线图            | P1  |
| **花钱Top榜** | 按支出类别生成饼图，展示各类花费占比         | P0  |
| **应收提醒**   | 基于手工录入的收入记录，标记“未收款”，手动更新状态 | P2  |
| **不做**     | 无标准财务报表（资产负债表等），不生成税务申报表   | —   |

### 4.5 模块四：基础设置

| 功能         | 说明                    | 优先级 |
| :--------- | :-------------------- | :-- |
| **企业信息**   | 公司名、统一社会信用代码（非必填）     | P1  |
| **支出类别管理** | 查看系统预设类别，修改别名         | P0  |
| **收入来源管理** | 预设收入来源（如“销售收款”、“服务费”） | P1  |

## 五、MVP 用户核心流程

### 5.1 核心场景：餐饮消费记账

1. **触发场景**：老板请客户吃完饭，拿到一张500元餐饮发票。
2. **操作**：打开电脑浏览器，登录“轻账目”Web端，点击“记一笔支出”。
3. **填写表单**：
   - 日期：自动默认今天
   - 金额：输入500
   - 摘要：输入“请客户吃饭”
   - 类别：系统根据“吃饭”自动选中“请客吃饭”（业务招待费别名）
4. **保存**：点击保存，记录进入收支列表。
5. **价值获取**：回到首页看板，今日支出增加了500元。点击“花钱Top榜”，看到“请客吃饭”这个类别本月已累计8000元，占比最高。

### 5.2 用户动线图

```
浏览器打开系统
    │
    ▼
  登录（简单账号密码）
    │
    ▼
  首页看板（本月收支、花钱排行）
    │
    ├──▶ 记一笔支出（表单录入）──▶ 自动归类 ──▶ 返回首页（数据更新）
    │
    ├──▶ 记一笔收入（表单录入）──▶ 返回首页（数据更新）
    │
    ├──▶ 收支列表（查看/编辑/删除）
    │
    └──▶ 设置（修改类别别名）
```

## 六、MVP 不做什么（边界控制）

| 不做的模块      | 说明               |
| :--------- | :--------------- |
| ❌ AI识别     | 无OCR、无语音、无自然语言处理 |
| ❌ 移动端/小程序  | 仅Web端，不开发小程序     |
| ❌ 发票拍照/扫码  | 手工录入代替           |
| ❌ 文件导入     | 无Excel/PDF导入     |
| ❌ 银行流水对接   | 无                |
| ❌ 多用户/权限   | 仅单人使用            |
| ❌ 税务申报     | 无                |
| ❌ 标准财务报表   | 不生成资产负债表、利润表     |
| ❌ 工资/资产/对账 | 无                |

**核心原则：**

- 手工录入为主，规则引擎辅助归类
- 零AI依赖，纯Web端
- 让老板看懂钱花哪了，而不是学会计

***

## 七、技术方案（MVP）

### 7.1 技术选型

| 组件      | 选型                                          | 说明                |
| :------ | :------------------------------------------ | :---------------- |
| **前端**  | Vue3 + Element Plus                         | 表单、表格、图表（ECharts） |
| **后端**  | Spring Boot 3                               | 规则引擎、RESTful API  |
| **数据库** | MySQL 8.0                                   | 存储收支记录、类别配置       |
| **部署**  | Docker Compose（Nginx + Spring Boot + MySQL） | 单机部署              |
| **认证**  | 简单JWT登录                                     | 单用户无需复杂权限         |

### 7.2 核心API（MVP）

| 端点                       | 方法     | 描述                |
| :----------------------- | :----- | :---------------- |
| `/api/auth/login`        | POST   | 登录                |
| `/api/transactions`      | POST   | 创建收支记录            |
| `/api/transactions`      | GET    | 查询收支列表（分页、筛选）     |
| `/api/transactions/{id}` | PUT    | 修改记录              |
| `/api/transactions/{id}` | DELETE | 删除记录              |
| `/api/categories`        | GET    | 获取支出/收入类别列表       |
| `/api/categories/{id}`   | PUT    | 修改类别别名            |
| `/api/dashboard/summary` | GET    | 首页看板数据（本月收支、分类汇总） |

### 7.3 规则引擎设计

- 使用简单的关键词匹配（Java 正则/contains）
- 预置规则配置文件，可扩展
- 前端可选类别，若自动匹配不准可手工修改

## 八、验证指标

| 指标         | 目标值           | 验证周期   |
| :--------- | :------------ | :----- |
| **周活跃天数**  | 平均每个老板 > 2天/周 | 上线后30天 |
| **日新增记录数** | 至少1笔/天        | 上线后30天 |
| **30日留存率** | ≥50%          | 上线后30天 |

**核心假设：**

> 如果老板愿意手工录入收支，说明“简单记账+自动归类+直观看板”的需求真实存在，可后续叠加AI录入、报表等高级功能。

## 十、关键风险与应对

| 风险        | 应对措施                          |
| :-------- | :---------------------------- |
| 老板不愿手工录入  | 极致简化表单，默认填充日期，规则自动匹配类别，减少操作步骤 |
| 自动归类不准    | 提供别名和手动修改，允许老板自定义规则           |
| Web端使用频率低 | 后续增加移动端适配，或者邮件/微信提醒           |
| 单用户无网络效应  | 通过“分享看板”功能实现口碑传播              |

***

以上为“轻账目”Web端MVP方案，聚焦纯手工录入、规则自动归类、直观看板，不包含任何AI能力，为后续演进奠定基础。
