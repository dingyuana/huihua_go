### 3.5 发票导入规则

**红冲识别规则（优先级）：**

| 优先级 | 判断条件 | 分类结果 |
|---|---|---|
| 1 | `价税合计 < 0` 或 `金额 < 0` | 红冲发票 |
| 2 | 状态列包含 "红冲" | 红冲发票 |
| 3 | 状态列包含 "作废" | 作废发票 |
| 4 | 以上都不是 | 正常发票 |

**两遍处理流程：**

1. **第一遍：数据收集** — 列名映射、行数据解析、状态分类、备注提取原发票号，将所有行数据收集到内存列表
2. **第二遍：按优先级排序处理** — 所有行按优先级排序（normal=0 → redflush=1 → voided=2 → redchar=3），单次循环中：
   - 优先创建正常发票（状态=issued，自动生成凭证）
   - 处理红冲发票时通过备注提取原发票号，匹配同批或历史正常发票并标记为 voided
   - 创建作废发票记录（状态=voided，不生成凭证）
   - 创建红字发票记录

**备注提取正则：** `r'被红冲蓝字(?:数电)?发票号码[：:]\s*(\d+)'`

**统一列名映射：** 系统内置 `COLUMN_ALIASES` 字典，支持多种 Excel 列名变体（如"发票号码"/"数电发票号"/"发票号"均可识别）

### 4.3 审核链设计

**当前实现：**
- 会计可完成制单与审核（暂不强制角色分离）
- 财务经理拥有审核/过账/冲红/反审核权限
- 所有操作日志记录操作人

**状态流转：** 草稿 → 待审核 → 已审核 → 已过账 → 已冲销

### 4.4 冲红账规则

| 规则项   | 说明                              |
| :---- | :------------------------------ |
| 触发方式  | Web 端凭证详情页点击"冲红"按钮（仅财务经理可见）      |
| 必填项   | 冲红原因（下拉：记账错误/重复记账/金额错误/科目错误/其他） |
| 生成结果  | 系统自动生成与原凭证借贷方向相反、金额相同的红字凭证      |
| 状态    | 红字凭证为"待审核"，需财务经理再次审核过账          |
| 原凭证状态 | 标记为"已冲销"，保留在账套中，不可修改            |
| 日志记录  | 记录冲红操作人、时间、原因、原凭证号、红字凭证号        |

## 十七、远期规划（AI 增强）

> **规划阶段：V2**，当前 V1 采用确定性规则映射，V2 引入 AI 能力提升科目匹配的准确性与灵活性。

### 17.1 AI 智能科目推荐

**目标：** 在用户录入凭证或业务单据生成凭证时，根据摘要/备注/业务描述自动推荐最匹配的会计科目，减少手工选择成本。

| 场景 | 当前做法（V1） | V2 增强 |
|:---|:---|:---|
| 手工凭证录入 | 用户手动选择科目 | 输入摘要后自动推荐科目候选列表 |
| 业务单据生成凭证 | 按确定性规则映射（费用类型/客户/供应商） | 结合摘要语义修正科目推荐，覆盖规则未覆盖的边界情况 |
| 银行流水生成凭证 | 按分类字段 switch-case 映射 | 根据银行摘要+对方户名自动推测科目 |
| 科目映射配置 | 管理员手动设置映射表 | 系统根据历史使用数据推荐默认映射 |

**核心能力：**
1. **摘要理解**：解析中文财务摘要（如"付xx公司货款"、"收客户回款"），提取业务实质
2. **科目排序**：按历史使用频率 + 业务相似度对推荐科目排序
3. **人工反馈学习**：记录用户对推荐结果的采纳/修改，持续优化推荐质量
4. **冷启动**：初始阶段基于规则兜底，积累足够数据后切换为 AI 推荐为主

### 17.2 AI 凭证草稿

**目标：** 用户通过自然语言描述即可自动生成完整凭证（多行借贷分录）。

```
输入示例："报销差旅费2000元，员工张三"
输出：借 6602.03 管理费用-差旅费 2000 / 贷 1002 银行存款 2000
```

### 17.3 实现策略

| 阶段 | 范围 | 说明 |
|:---|:---|:---|
| V1（当前） | 确定性规则 | 按预设映射表/分类规则生成科目，见 §1.7 模块一 |
| V2.1 | 摘要分词+规则增强 | 引入中文分词提取关键词，扩展规则匹配弹性 |
| V2.2 | AI 推荐辅助 | 在规则无法覆盖时，调用轻量模型推荐科目，人工确认后生效 |
| V2.3 | AI 全自动推荐 | 默认使用 AI 推荐，保留规则兜底和人工覆盖能力 |
