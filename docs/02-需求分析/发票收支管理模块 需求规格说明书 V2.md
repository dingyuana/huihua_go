### 0. 核心约束声明

> - **业票分离，单据驱动**：发票是业务发生的“证据”，其录入不直接产生账务影响。应收账款/应付账款的确立，以及资金的收付核销，必须通过独立的“收款单/付款单/凭证”来完成。
> - **AI为辅，人审为终**：系统AI在信息提取、分类、匹配等环节提供高效辅助，但**发票信息的确认、三单匹配的确认、核销动作的确认，最终都必须由人工点击“确认”按钮完成**。系统不执行任何“自动确认”或“自动核销”的关键操作。
> - **状态严格，流程闭环**：发票全生命周期由其“状态”严格定义和驱动。任何操作导致的状态变更，都必须是可追溯、可审计的，并最终导向完整的业务与账务闭环。

### 1. 模块定位

本模块是“单据→凭证→审核→结转→分析”链条中“单据层”的核心，负责对企业在经营活动中产生的**销售发票（对外开具）**、**采购发票（自外收取）** 和**费用发票（自外收取）** 进行全生命周期的数字化管理，并与后续的收款、付款、报销流程形成完整闭环。

---

### 2. 整体业务流

```
【发票流】                                【账务与资金流】

【销售侧】
（多种方式）录入销售发票 → 确认发票 → [生成应收] → 收款单核销 → 核销完成
    ↑                         ↓                        ↑
    批量导入（税务局文件）    应收明细账               银行流水

【采购侧】
（多种方式）录入采购发票 → 三单匹配 → 确认发票 → [生成应付] → 付款单核销 → 核销完成
    ↑                         ↓                        ↑
    手工/OCR/AI               入库单/订单               银行流水

【费用侧】
（多种方式）录入费用发票 → 确认发票 → 报销/直接生成凭证 → 凭证过账
    ↑                         ↓
    OCR识别/AI分类           费用报销单
```

### 3. 发票类型定义与导入方式总览

| 发票类型 | 说明 | 支持的录入方式 |
| :--- | :--- | :--- |
| **销售发票** | 企业开具给客户的发票，用于确立应收账款。 | **1. 电子税务局表格批量导入 (核心新增)** <br>2. 手工录入<br>3. OCR拍照/图片识别<br>4. API系统对接 |
| **采购发票** | 供应商开具给企业的发票，用于确立应付账款。 | 1. 手工录入<br>2. OCR拍照/图片识别<br>3. API系统对接（如供应商协同平台） |
| **费用发票** | 员工报销或对公支付的费用类发票。 | 1. 手工录入<br>2. **OCR拍照/图片识别 (重点场景)**<br>3. 批量导入（如电子发票PDF/OFD合集） |

### 4. 发票全生命周期状态

| 状态 | 说明 | 适用发票类型 |
| :--- | :--- | :--- |
| `草稿` | 经任意方式录入或导入，信息待完善或待确认。 | 全部 |
| `三单匹配中` | (仅采购发票) 系统正在或已完成与采购订单/入库单的自动比对，等待人工处理。 | 采购发票 |
| `已确认` | 发票信息已由人工确认无误，正式进入财务系统。此时，销售/采购发票会生成相应的应收/应付记录。 | 全部 |
| `部分核销` | 已有部分金额与收款单/付款单关联核销，尚有余额未结清。 | 销售/采购发票 |
| `已核销` | 发票金额已与收款单/付款单完全核销，款项结清。 | 销售/采购发票 |
| `已生成凭证` | (仅费用发票) 发票已关联报销单并生成凭证，或直接生成了费用凭证。 | 费用发票 |
| `已归档` | 业务完结且超过规定保存期的发票，转入归档状态，不可编辑。 | 全部 |

### 5. 核心功能详细设计

#### 5.1 统一发票工作台

所有类型发票的统一管理入口，提供清晰的导航、多维度视图和任务导向的操作。

**5.1.1 界面布局**
- **顶部**：二级导航Tab页签，【全部】、【销售发票】、【采购发票】、【费用发票】，支持角标显示各状态下待处理数量。
- **操作区**：放置全局操作按钮。
    - **销售发票Tab下**：高亮显示【导入销售发票】，次要按钮【手工录入】。
    - **采购/费用发票Tab下**：主要按钮【手工录入】、【OCR识别录入】。
- **列表区**：动态表头，状态字段使用不同颜色标签（如`草稿`灰色，`已确认`蓝色，`已核销`绿色，`三单匹配中`橙色）。
- **筛选区**：提供发票状态（多选）、客户/供应商、日期范围、金额范围等筛选条件。

#### 5.2 销售发票管理

##### 5.2.1 批量导入（电子税务局表格文件）**【新增核心功能】**

**业务背景**：企业财务人员通常需定期从电子税务局导出开票汇总表（通常为Excel或CSV格式），其中包含了多张已开具发票的明细数据。将此文件直接导入系统，可极大提升效率，避免人工逐笔录入的错误。

**流程：**
```
下载模板/导出税局文件 → 上传文件 → 系统预校验与AI查重 → 数据预览与人工修正 → 确认导入
```

**交互设计详解：**

1.  **入口触发**：点击销售发票列表页的【导入销售发票】按钮，弹出导入向导对话框。
2.  **步骤一：文件上传与模板匹配**
    - **上传区域**：支持拖拽或点击上传`.xlsx`, `.csv`文件。
    - **模板管理**：系统预置“电子税务局标准模板”，并支持用户配置“自定义模板映射”。
        - **选择模板**：下拉框选择【电子税务局-全电发票导出】或【自定义模板A】。
        - **字段映射**（首次使用或配置时）：系统展示文件表头，用户需将文件列与系统字段（发票号、客户名称、价税合计、开票日期等）进行拖拽或下拉匹配。系统自动保存此映射关系。
3.  **步骤二：系统预校验与AI查重**
    - 系统在后台异步执行以下任务，并在界面上显示进度条：
        - **格式校验**：检查必填字段（客户、金额、日期）是否为空，金额/税率格式是否正确。
        - **合规性校验**：校验发票号码位数。
        - **AI智能查重**：将导入数据中的发票号码、金额与系统中`已确认`、`部分核销`、`已核销`状态的发票进行比对。**高亮标记疑似重复的发票行**，并提示“疑似重复，请确认是否仍导入”。
4.  **步骤三：数据预览与人工修正**
    - 以全屏可编辑表格形式展示所有待导入数据。
    - **视觉与交互**：
        - **校验结果列**：新增一列“校验状态”，通过（绿色）、警告（黄色，如非必填项缺失）、错误（红色，如必填项缺失或格式错误）。
        - **错误行**：红色高亮，且该行的“导入”复选框默认不勾选。鼠标悬停显示具体错误信息。
        - **AI查重标记**：在发票号旁显示警告图标，悬浮显示“系统发现疑似重复发票：{发票号}，金额：{金额}元，日期：{日期}。确认导入？。
        - **人工修正**：用户可直接在表格中双击单元格，修正错误或补充信息（如自动匹配系统内的客户档案）。
5.  **步骤四：确认导入**
    - 点击【确认导入】，所有通过校验且被勾选的发票，将以`草稿`状态批量存入系统。导入完成后，弹窗显示导入结果摘要：“共解析XX条，成功导入XX条，跳过XX条，错误XX条”。支持下载错误报告。

##### 5.2.2 发票确认与核销

- **发票确认**：在列表或详情页，对`草稿`状态的发票执行【确认】操作。系统弹出二次确认框，明确提示“确认后将自动生成应收账款记录”。确认后，状态变为`已确认`。
- **收款核销**：
    - 此操作不在发票模块进行，而是在创建和编辑“收款单”时实现。
    - 收款单创建界面，选择客户后，【待核销发票】区域会自动加载该客户所有状态为`已确认`和`部分核销`的销售发票。
    - **AI核销推荐**：AI根据收款金额、打款方户名、发票金额、到期日等，自动匹配最可能的发票组合，高亮并预填“本次核销金额”。**此项推荐必须经人工核对、修改，并最终点击收款单的“过账”按钮方可生效。**
    - **结果**：核销完成后，发票状态根据余额自动变更为`部分核销`或`已核销`。

#### 5.3 采购发票管理

##### 5.3.1 三单匹配（核心逻辑视图）

采购发票保存后，状态为`草稿`，用户可点击【启动三单匹配】，进入专用处理视图。

- **布局**：三栏式结构。
    - **左栏（基准）**：采购发票详情，列出所有商品行。
    - **中栏（匹配单据）**：系统根据供应商、商品，列出匹配到的采购订单和入库单。
    - **右栏（结果与操作）**：图形化展示匹配结果。对每个商品行，清晰展示“订单数量vs入库数量vs发票数量”的比对，差异用红色高亮。
- **AI智能匹配**：系统自动关联，并给出匹配评分。完全匹配项，自动标注为可确认；部分匹配或不匹配项，给出差异原因分析（如：数量短缺、价格差异）。
- **人工决断**：
    - **完全匹配**：可一键【批量确认】。
    - **有差异**：提供【强制确认】按钮，点击时**强制要求**填写“差异原因”与“处理方式”（如：挂账、折让、退货），并指定审批人或责任人。确认后，状态变为`已确认`，并生成应付账款记录。

##### 5.3.2 付款核销

逻辑同销售发票的收款核销，此操作发生在“付款单”创建与编辑流程中，关联状态为`已确认`或`部分核销`的采购发票。

#### 5.4 费用发票管理

##### 5.4.1 智能识别与科目推荐

- **录入重点**：通过OCR识别发票时，系统会调用AI模型，根据商户名称、商品名等信息，自动进行费用类型分类（如：从“美团”识别为“业务招待费”，从“中国石化”识别为“车辆费”）。
- **交互**：在发票确认弹窗中，清晰展示“AI识别费用类型：**差旅费**（置信度95%）”，并提供【采纳此类型】和【手动选择】两个选项。若置信度低于80%，则不展示推荐，直接要求用户手动选择。
- **后续处理**：
    - 确认后，状态变为`已确认`，但不生成应付款。
    - 用户可选择【转为报销单】或【直接生成凭证】。
    - 若【直接生成凭证】，系统进入凭证草稿页，并根据已确认的费用类型，自动填列借方科目。

#### 5.5 核销记录追溯

- **入口**：任何发票详情页，均设有【核销记录】选项卡。
- **内容**：以时间轴形式，清晰展示该发票被哪些收/付款单进行了核销。
- **数据**：每条记录包含关联单号（可点击穿透）、核销金额、核销日期、操作人、对应银行流水号（如有）。
- **对于费用发票**：【核销记录】选项卡替换为【凭证记录】，显示关联生成的凭证号、报销单号。

### 6. AI能力应用矩阵

| 环节 | AI能力 | 详细描述 | 触发方式 | 输出 |
| :--- | :--- | :--- | :--- | :--- |
| **发票录入** | OCR识别 | 识别上传的发票图片/PDF，提取结构化信息。 | 用户上传图片 | 回填到录入表单的字段值 |
| **批量导入** | **智能查重与合规检查** | 在导入过程中，检查发票号、金额是否与库内数据重复，检查发票号格式合规性。 | 用户上传文件 | 在预览界面高亮疑似重复或不规范的行 |
| **发票分类** | 语义分类 | 根据发票内容（如商品、商户名）自动判断属于销售、采购还是费用发票。 | 录入或OCR识别后 | 推荐发票类型 |
| **科目推荐** | 费用归类与科目映射 | 对费用发票，分析其内容，推荐费用类型及对应的借方会计科目。 | 费用发票确认时 | 费用类型标签、借方科目 |
| **三单匹配** | 单据关联匹配 | 自动寻找与采购发票匹配的采购订单和入库单，并计算匹配度。 | 采购发票草稿状态 | 匹配结果视图，标记完全/部分/不匹配 |
| **核销推荐** | 智能勾稽 | 在创建收/付款单时，根据金额、往来单位，自动推荐待核销的发票清单及金额。 | 收/付款单选择客户/供应商后 | 高亮的待核销发票列表，预填核销金额 |

### 8. 状态流转详解

**销售发票**：
```
[批量导入/手工/OCR] → 草稿 → 已确认 → 部分核销 → 已核销 → 已归档
```

**采购发票**：
```
[手工/OCR] → 草稿 → 三单匹配中 → 已确认 → 部分核销 → 已核销 → 已归档
```

**费用发票**：
```
[手工/OCR] → 草稿 → 已确认 → 已生成凭证 → 已归档
```
