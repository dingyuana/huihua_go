### 0. 核心约束声明

> - **行项目驱动导入**：电子税务局导出的 Excel 每行代表发票的一个行项目（货物/劳务明细），同一发票号的多行数据应合并为一条发票记录，行项目独立存储。
> - **导入批次隔离**：同一次导入操作内允许重复发票号（合并为一条发票），但不允许与系统中已存在的发票号冲突。
> - **数据完整性**：发票的标识信息（发票号码、代码、票种）、财务信息（金额、税额）、商品明细（货物名称、数量、单价、税率）必须完整导入。
> - **红字发票关联**：红字发票必须通过备注信息关联到原蓝字发票，确保冲销关系可追溯。

---

### 1. 模块定位

本次需求是对现有销售发票导入功能的**增强改进**，聚焦于：

1. **导入数据模型修正**：从"一行一条发票"改为"一组行项目合并为一条发票"
2. **发票唯一性约束调整**：允许系统内存在相同发票号（用于红蓝冲销等场景）
3. **行项目导入**：解析并存储商品/劳务明细
4. **红字发票识别增强**：正确识别正数/红字发票，从备注提取蓝字关联
5. **列表显示优化**：序号、条件展开、红字状态等

### 2. 现状与问题分析

#### 2.1 当前实现

| 维度 | 当前行为 | 问题 |
|------|---------|------|
| 导入粒度 | 每 Excel 行 → 一条 `sales_invoices` 记录 | 同一发票多行项目变成多条独立发票 |
| 发票号唯一性 | `invoice_no VARCHAR(50) UNIQUE NOT NULL` | 重复行被 `ON CONFLICT DO NOTHING` 静默跳过 |
| 行项目导入 | ❌ 未实现 | 货物名称、数量、单价等字段全部丢失 |
| 红字识别 | 逻辑反转（第1期已修复） | 无 |
| 蓝字关联 | 依赖独立列"对应蓝字发票号" | 实际 Excel 无此列，信息在备注中 |
| 发票票种 | 第1期已添加 `invoice_category` 列 | 无 |

### 3. 功能需求

#### FR-01: 列表显示序列号

| 项目 | 内容 |
|------|------|
| **ID** | FR-01 |
| **标题** | 发票列表增加行序号 |
| **优先级** | P1 - 体验优化 |
| **描述** | 发票工作台列表每行显示递增序号，方便用户定位和沟通 |
| **验收标准** | 1. 序号从 1 开始递增<br>2. 筛选/搜索后序号连续<br>3. 序号列宽度 60px |

#### FR-02: 同导入批次内重复发票号合并

| 项目 | 内容 |
|------|------|
| **ID** | FR-02 |
| **标题** | 重复发票号归并为一条含多个行项目的发票 |
| **优先级** | P0 - 核心功能 |
| **描述** | 电子税务局导出的 Excel 中，同一发票号出现多次（对应不同货物明细）。导入时应合并为一条发票记录，子项写入 `invoice_line_items` 表 |
| **验收标准** | 1. 同 `invoice_no` 的多行合并为 1 条 `sales_invoices`<br>2. 每行的货物名称/数量/单价作为子项写入 `invoice_line_items`<br>3. 发票头金额 = 所有子项金额汇总<br>4. 所有子项共享同一个发票头 ID |
| **数据流** | Excel 行 → 按 `invoice_no` 分组 → 1 条 `SalesInvoice` + N 条 `InvoiceLineItem` |

#### FR-03: 跨导入批次重复发票号拦截

| 项目 | 内容 |
|------|------|
| **ID** | FR-03 |
| **标题** | 禁止与系统中已存在的发票号冲突 |
| **优先级** | P0 - 核心功能 |
| **描述** | 导入前校验文件内所有发票号，若任一已在系统中存在，则拒绝本次导入并提示冲突 |
| **验收标准** | 1. 导入前批量查重<br>2. 存在冲突时返回冲突列表，阻塞导入<br>3. 零冲突时正常导入 |
| **异常处理** | 冲突时不清除已选文件，用户修正后重新导入 |

#### FR-04: 仅多行项目发票显示展开图标

| 项目 | 内容 |
|------|------|
| **ID** | FR-04 |
| **标题** | 条件性展开箭头 |
| **优先级** | P2 - 体验优化 |
| **描述** | 仅有 0 或 1 个子项的发票，不显示 `>` 展开图标；≥2 个子项时正常显示 |
| **验收标准** | 1. `line_items.length <= 1` 时展开图标隐藏<br>2. `line_items.length >= 2` 时展开图标正常显示<br>3. 展开/折叠功能正常 |

#### FR-05: 红字列改为状态显示

| 项目 | 内容 |
|------|------|
| **ID** | FR-05 |
| **标题** | 红字状态标签 |
| **优先级** | P1 - 体验优化 |
| **描述** | 红字列改为状态标签：`is_return=false` 显示"正常"（绿色），`is_return=true` 显示"红字"（红色） |
| **验收标准** | 1. 正常发票显示绿色"正常"标签<br>2. 红字发票显示红色"红字"标签 |

#### FR-06: 从备注提取对应蓝字发票号

| 项目 | 内容 |
|------|------|
| **ID** | FR-06 |
| **标题** | 红字发票蓝字关联信息自动提取 |
| **优先级** | P0 - 核心功能 |
| **描述** | 红字发票导入时，从备注文本中自动提取原蓝字发票号，存入 `source_red_invoice_no` 字段 |
| **提取规则** | 正则匹配：`对应蓝字发票号[：:]\s*(\S+)` / `原蓝字发票号[：:]\s*(\S+)` / `红冲原发票[：:]\s*(\S+)` / `原发票号[：:]\s*(\S+)` |
| **验收标准** | 1. 红字发票从备注中成功提取蓝字号<br>2. 提取结果可在"对应蓝字发票"列显示<br>3. 无法提取时不阻塞导入，`source_red_invoice_no` 留空 |
| **优先级** | 独立列 > 备注提取：如果 Excel 有独立"对应蓝字发票号"列，优先使用列值 |

### 5. 数据模型变更

#### 5.1 sales_invoices 表

```sql
-- 变更: 解除 UNIQUE 约束
ALTER TABLE sales_invoices DROP CONSTRAINT sales_invoices_invoice_no_key;
CREATE INDEX idx_sales_invoices_invoice_no ON sales_invoices(invoice_no);
```

#### 5.2 invoice_line_items 表（已有，无需变更）

```sql
CREATE TABLE IF NOT EXISTS invoice_line_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    invoice_id UUID NOT NULL REFERENCES sales_invoices(id),
    item_code VARCHAR(50),
    description VARCHAR(500) NOT NULL,
    quantity DECIMAL(18,4) DEFAULT 1,
    unit_price DECIMAL(18,4) DEFAULT 0,
    tax_rate DECIMAL(18,4) DEFAULT 0,
    tax_amount DECIMAL(18,2) DEFAULT 0,
    net_amount DECIMAL(18,2) DEFAULT 0,
    total_amount DECIMAL(18,2) DEFAULT 0,
    unit VARCHAR(20),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 6. 导入处理流程

```
用户上传 Excel
       │
       ▼
解析所有行，构建列映射
       │
       ▼
前置校验:
  ├── 日期格式校验
  ├── 金额校验
  └── 跨导入重复校验 (批量查 DB)
       │
       ▼ (校验通过)
按 invoice_no 分组
       │
       ▼
每组生成:
  ├── 1× SalesInvoice (表头)
  │   ├── 金额 = 组内子项汇总
  │   ├── isReturn 从"是否正数发票"列判定
  │   └── sourceRedInvoiceNo 从备注提取
  └── N× InvoiceLineItem (子项)
      ├── 货物名称 / 规格 / 单位
      ├── 数量 / 单价 / 税率 / 税额
      └── 不含税金额 / 价税合计
       │
       ▼
事务批量写入
       │
       ▼
返回导入结果 (头数, 行数, 失败详情)
```
