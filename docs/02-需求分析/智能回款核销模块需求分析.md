# 业财一体化核销模块需求分析说明书

## 1 引言

### 1.1 编写目的

明确财务系统中"业财一体化核销"子模块的功能边界与业务逻辑，解决企业日常经营中**发票（业务流）**、**收付款单（资金流）**和**银行流水（实物流）**三者之间的匹配核销难题，实现从"业务发生"到"资金收付"再到"账务核销"的自动化与规范化闭环。

### 1.2 核心设计原则

#### 原则一：权责发生制与收付实现制分离

| 维度 | 说明 | 代表单据 |
|---|---|---|
| **权责发生制** | 记录业务完成（债权债务确立），与实际收付款时间无关 | 发票 → 应收单/应付单 |
| **收付实现制** | 记录实际资金变动，与业务发生时间无关 | 银行流水 → 收付款单 |

发票代表业务完成，银行流水代表资金变动。两者必须通过**收/付款单**进行关联和核销，确保业务流与资金流可独立追踪。

#### 原则二：单据驱动凭证

财务凭证**原则上不应手工录入**，而应由业务单据（发票、收付款单）自动生成，保证账实相符、账证相符。

```
业务单据（发票/收付款单） → 自动生成会计凭证 → 过账 → 报表
```

#### 原则三：闭环管理

- **每一笔银行流水必须有去处**：核销或挂账
- **每一张发票必须有结果**：已收款或坏账
- **每一个收付款单必须有依据**：关联发票或银行流水

### 1.3 适用范围

本需求适用于系统中的【应收管理】【应付管理】【资金管理-回款核销】模块，涵盖发票管理、收付款单管理、银行流水核销全流程。

---

## 2 角色与权限矩阵 (RACI)

为确保"钱账分管"的内控合规性，系统需严格限制不同角色的操作权限：

| 角色 | 核心职责 | 关键权限说明 |
|---|---|---|
| **出纳** | 资金流水导入与初筛 | 拥有银行流水的增删改查权；可将流水标记为"待认领"；**无权**执行最终的发票核销操作 |
| **应收会计** | 回款认领审核与核销 | 拥有"待认领资金池"的操作权；可执行流水与发票的匹配、拆分与核销；**无权**修改原始银行流水数据 |
| **销售人员** | 协助确认款项归属 | 可查看自己负责客户的未认领款项；可发起"认领申请"（建议打款对应哪笔订单）；**无直接核销权** |
| **财务经理** | 审计与追溯 | 可查看完整的核销操作日志；可执行核销反冲；可查看资金流向与业务依据 |

## 3 详细业务场景与功能需求

### 3.1 场景一：发票管理（业务流）

**目标：** 记录应收/应付账款，确立债权/债务。

#### FR-10 发票录入/导入

系统需支持增值税专用发票、普通发票、数电票的导入与手工录入。

**验收标准：**
- 支持 Excel 批量导入（两遍处理引擎：收集数据 → 按优先级排序处理）
- 支持手工录入单张发票
- 自动识别字段：发票代码、发票号码、金额、税额、开票日期、购方/销方信息
- 发票查重：同一发票号码不可重复导入
- 红冲/作废识别：
  - 负数金额 → 红冲发票
  - 状态列含"红冲" → 红冲发票
  - 状态列含"作废" → 作废发票
- 红冲发票通过备注提取原发票号（正则：`被红冲蓝字(?:数电)?发票号码[：:]\s*(\d+)`）+ 金额匹配原发票

#### FR-11 发票审核与入账

**动作：** 用户确认发票无误，执行"审核入账"。

**系统逻辑：**
1. 生成应收单/应付单（中间表，用于记录未核销金额）
2. 自动生成记账凭证：
   - 借：应收账款 / 应付账款
   - 贷：主营业务收入 / 相关成本
   - 贷：应交税费-应交增值税（销项税额）
3. 状态变更：发票状态变为 `pending_payment`（待收款/待付款）

**验收标准：**
- 审核人不可为发票导入人（SaaS 阶段强制）
- 审核通过后自动生成凭证，不可修改
- 发票状态从 `draft`（草稿）→ `pending_payment`（待收款）
- 凭证摘要：`[客户/供应商名称] 开具发票 [发票号码]，金额 [xxx] 元`

#### FR-12 红字发票处理（红冲）

**逻辑：** 红字发票必须关联原蓝字发票。

**系统动作：**
1. 生成红字应收/应付单（负数）
2. 自动生成红字凭证（负数凭证，冲减原分录）
3. 更新原蓝字发票状态为 `red_flushed`（已红冲）

**验收标准：**
- 红字发票导入时自动关联原蓝字发票
- 自动生成负数凭证：
  - 借：应收账款（红字）
  - 贷：主营业务收入（红字）
  - 贷：应交税费（红字）
- 原蓝字发票的未核销余额扣减
- 原蓝字发票状态变更为 `red_flushed`

### 3.2 场景二：收/付款单管理（资金流桥梁）

**目标：** 作为发票与银行流水的连接器，管理"该收/付的钱"与"实际收/付的钱"之间的关系。

#### FR-13 收/付款单的来源

**来源 A：由发票生成（计划收款）**

在查看发票详情页时，点击"生成收款单"。此时生成的是"计划收款单"或"待核销收款单"，金额为发票金额。

**验收标准：**
- 发票详情页显示"生成收款单"按钮
- 生成收款单时自动带出：客户名称、发票号码、发票金额、到期日期
- 收款单状态：`pending`（未核销）
- 收款单类型：`by_invoice`（按发票）

**来源 B：由银行流水生成（预收款/现结）**

在银行流水页面，针对某笔进账，点击"立账/生成收款单"。用于处理没有发票的预收款或现结业务。

**验收标准：**
- 银行流水列表每条记录显示"生成收款单"按钮
- 生成收款单时自动带出：对方户名、流水金额、交易日期
- 收款单类型：`prepayment`（预收款）或 `cash_settlement`（现结）
- 预收款状态：`pending_invoice`（待关联发票）
- 现结状态：`pending`（未核销）

**来源 C：手工新增（零星收支）**

用于处理零星收支、非业务款项等。

**验收标准：**
- 收付款单列表页显示"新增"按钮
- 手工录入字段：客户/供应商、金额、收支类型、摘要、关联银行账号
- 收款单类型：`manual`（手工）

#### FR-14 收/付款单的状态流转

| 状态 | 说明 | 触发条件 |
|---|---|---|
| `pending` | 未核销 | 单据已生成，但未与银行流水或发票匹配 |
| `partial_reconciled` | 部分核销 | 已匹配部分金额（例如分期付款） |
| `reconciled` | 已核销 | 金额完全匹配，债权债务结清 |
| `prepayment` | 预收款 | 由银行流水生成的预收款，待关联发票 |
| `cancelled` | 已取消 | 手工取消的单据 |

**验收标准：**
- 收付款单列表支持按状态筛选
- 部分核销时显示：已核销金额 / 未核销金额
- 已核销单据不可删除，只可查看
- 取消操作记录审计日志

### 3.3 场景三：银行流水管理（实物流）

**目标：** 记录真实资金变动，完成最终的"清账"。

#### FR-01 流水导入

系统需支持标准 Excel/CSV 模板批量导入银行交易明细，并具备字段映射配置功能（如日期、金额、对方户名、摘要）。

**验收标准：**
- 支持 .xlsx / .xls / .csv 格式
- 提供标准模板下载
- 导入时自动识别列名（支持常见变体：如"交易日期"/"发生日期"/"入账日期"）
- 编码自动检测：兼容 UTF-8、GBK、GB18030 等编码
- 导入预览：展示解析结果，支持确认/取消
- 导入日志：记录导入人、时间、文件名称、成功条数、失败条数

#### FR-15 自动核销（理想情况）

**规则：** 银行流水摘要包含"发票号123" + 金额一致。

**系统动作：**
1. 自动找到对应的"发票生成的应收单"
2. 将银行流水与该应收单进行核销
3. 发票状态变"已结清"，流水状态变"已处理"
4. 自动生成收款凭证（若未生成）

**验收标准：**
- 匹配规则可配置：
  - 摘要包含发票号码（精确匹配）
  - 对方户名 = 客户名称 且 金额一致
  - 对方账号 = 客户银行账号 且 金额一致
- 自动核销结果在核销界面以"自动处理"标签展示
- 支持人工复核后确认或撤销

#### FR-16 半自动核销（认领）

**场景：** 流水进来了，但系统里没有对应的发票（可能是预收款，或发票还没开）。

**动作：**
1. 系统将流水标记为 `pending_claim`（待处理）
2. 财务人员基于这笔流水，新建一张收款单（类型为"预收款"或"不明款项"）
3. 流水与该收款单核销
4. 待未来发票开具后，再将发票与该预收款单进行对冲（或红冲预收，转正应收）

**验收标准：**
- 待认领流水在"待认领资金池"中展示
- 支持出纳标记为"业务回款"或"非业务款项"
- 支持销售协同认领（销售人员可发起认领申请）
- 预收款单与发票关联后，自动生成结转凭证：
  - 借：预收账款
  - 贷：应收账款

#### FR-17 多对多核销

**场景：** 一笔流水 100 万，对应 3 张发票。

**动作：** 在核销界面，勾选该笔流水，再勾选 3 张发票生成的应收单，系统自动按比例或指定金额进行拆分核销。

**验收标准：**
- 核销界面采用**左右分栏设计**：左侧为银行流水列表，右侧为待选发票/应收单列表
- 支持一笔流水核销多张发票（多对一）
- 支持一张发票分多次收款（一对多）
- 支持手动指定每笔核销金额
- 系统自动计算：流水金额 vs 发票总额，差额实时显示
- 尾差处理（见 FR-07）

### 3.4 场景四：凭证自动化逻辑

**目标：** 确保财务账务数据准确，业务单据自动生成凭证。

#### FR-18 业务动作与会计分录映射

| 业务动作 | 触发单据 | 生成的会计分录（示例） | 备注 |
|---|---|---|---|
| 开具发票 | 销售发票 | 借：应收账款<br>贷：主营业务收入<br>贷：应交税费-销项税 | 确认收入与债权 |
| 收到款项 | 收款单（关联流水） | 借：银行存款<br>贷：应收账款 | 债权转为资金 |
| 红字冲销 | 红字发票 | 借：应收账款（红字）<br>贷：主营业务收入（红字）<br>贷：应交税费（红字） | 冲减原分录 |
| 退款 | 付款单（关联流水） | 借：应收账款（或红字应收）<br>贷：银行存款 | 实际退款 |
| 预收款到账 | 收款单（预收款） | 借：银行存款<br>贷：预收账款 | 预收确认 |
| 预收转应收 | 预收款单关联发票 | 借：预收账款<br>贷：应收账款 | 预收结转 |
| 采购发票入账 | 采购发票 | 借：原材料/库存商品<br>借：应交税费-进项税<br>贷：应付账款 | 确认采购与债务 |
| 支付款项 | 付款单（关联流水） | 借：应付账款<br>贷：银行存款 | 债务清偿 |

**验收标准：**
- 每个业务动作触发后自动生成对应凭证
- 凭证科目可通过科目映射配置
- 凭证摘要自动填充业务上下文（客户名称、发票号、流水号等）
- 凭证生成失败时记录错误日志，不阻塞业务流程
- 支持凭证生成后人工审核（审核链）

### 3.6 阶段二：智能匹配与人工认领（责任人：系统/销售/会计）

#### FR-05 智能预匹配规则

系统需在后台实时运行匹配算法，将【待认领资金池】中的流水与【未结清销售发票】进行比对。满足以下任一条件即可标记为"系统推荐匹配"：
- **付款方名称与客户档案名称完全一致，且金额相等**
- **银行流水摘要中包含有效的发票号码或合同编号**

**验收标准：**
- 匹配策略可配置（精确匹配/模糊匹配/金额容差）
- 匹配结果在核销界面以"系统推荐"标签展示
- 支持按匹配度排序（100% 金额匹配 > 名称匹配 > 摘要包含发票号）
- 匹配响应时间：十万级未核销发票数据量下不超过 3 秒

#### FR-06 销售协同认领

对于备注不清的款项，系统应提供"指派给销售确认"功能。销售人员在移动端或PC端收到通知后，可填写建议关联的合同或客户，并提交给会计参考。

**验收标准：**
- 销售可登录系统，在"我的回款"页面查看到包含其负责客户名称的"待认领"流水
- 销售可点击"发起认领"，在弹窗中选择关联的客户及具体的销售订单/发票号
- 销售可填写备注说明（如"客户张三打款，对应合同 HT2023001"）
- 提交后，流水状态更新为 `sales_suggested`（销售已建议）
- 会计核销界面高亮显示销售的推荐结果

#### FR-07 复杂场景处理

**多对一核销：** 支持一笔银行流水同时勾选多张销售发票进行核销（例如客户合并支付三笔货款）

**一对多核销：** 支持一笔大额银行流水拆分为多次核销（例如客户预付10万，分三次发货开票抵扣）

**尾差处理：** 当实收金额与发票金额存在微小差异（如手续费扣除导致的几分钱差额）时，允许会计在核销界面录入"尾差金额"，并选择计入"财务费用-手续费"或"营业外收支"

**验收标准：**
- 多对一核销：勾选多张发票，系统自动计算发票总额，与流水金额比对
- 一对多核销：支持手动输入本次核销金额，系统自动更新发票剩余未核销余额
- 尾差处理：差额在预设阈值内（默认 ±5 元）时弹出尾差处理框，允许选择处理方式：
  - 计入"财务费用-手续费"（科目代码 6603）
  - 计入"营业外收入/支出"（科目代码 6301/6711）
  - 手动调整
- 尾差金额自动生成对应分录

### 3.7 阶段三：最终核销与状态更新（责任人：应收会计）

#### FR-08 执行核销

会计在核对无误后，点击"确认核销"。系统需执行以下原子操作：
- 将该笔银行流水的状态更新为"已核销"，并从【待认领资金池】移除
- 将关联的销售发票状态更新为"已收款"或"部分收款"，并扣减相应的未核销余额
- 自动生成收款记账凭证（借：银行存款，贷：应收账款），并传递至总账模块

**验收标准：**
- 核销操作为事务性操作：要么全部成功，要么全部回滚
- 核销完成后：
  - 流水状态变为 `reconciled`（已核销）
  - 发票状态变为 `paid`（全额收款）或 `partial_paid`（部分收款）
  - 自动生成 AccVoucher 凭证：
    - 借：银行存款（科目代码 1002）
    - 贷：应收账款（科目代码 1122）
  - 凭证摘要：`收到[客户名称]回款，核销流水[ID:xxx]`
- 核销界面提供确认提示，展示核销摘要（流水金额、关联发票数、尾差处理）

#### FR-09 核销反冲（红冲）

若发现核销错误，会计可在一定期限内（如当月结账前）执行"取消核销"操作，系统将逆向恢复流水状态和发票欠款余额，并删除对应的收款凭证。

**验收标准：**
- 仅应收会计/财务经理可执行反冲操作
- 反冲条件：所属账期未结账
- 反冲执行：
  - 流水状态恢复为 `pending_claim`（待认领）
  - 发票状态恢复为核销前状态（`issued` 或 `partial_paid`）
  - 发票未核销余额恢复
  - 自动生成反冲凭证（红字）或删除原收款凭证（根据凭证状态）
  - 记录反冲日志：`[时间] 用户[xxx] 执行了反冲操作：取消流水[ID:xxx] 与 发票[ID:xxx] 的核销，金额：xxx元`

## 4 数据需求与逻辑约束

### DR-01 数据一致性

银行流水表的 **核销金额** 总和必须等于关联发票表的 **本次核销金额** 总和。

**实现方式：**
- 核销操作在数据库事务中执行
- 核销前校验：`SUM(流水核销金额) == SUM(发票本次核销金额)`
- 校验不通过则回滚事务

### DR-02 唯一性约束

同一笔银行流水的子项不能被重复核销（除非是合法的拆分核销，且拆分总额不超过流水总额）。

**实现方式：**
- `cash_reconciliation` 表记录每笔核销明细（流水ID、发票ID、核销金额）
- 插入前校验：`SUM(该流水已核销金额 + 本次核销金额) <= 流水总金额`
- 违反约束时返回错误：`核销总额不能超过流水金额（当前已核销：xxx，本次：xxx，流水总额：xxx）`

### DR-03 审计日志

所有认领、匹配、核销、反冲操作，必须记录操作人ID、操作时间、变更前后的数据快照，以备审计追踪。

**实现方式：**
- `audit_logs` 表扩展记录类型：`reconciliation`（核销操作）
- 记录字段：
  - `action`：`claim` / `reconcile` / `reverse` / `suggest`
  - `entity_type`：`bank_transaction` / `receivable_invoice` / `reconciliation`
  - `before_data`：变更前的 JSON 快照
  - `after_data`：变更后的 JSON 快照

## 5 非功能性需求

### 5.1 性能要求

| 指标 | 要求 |
|---|---|
| 智能预匹配响应时间 | 十万级未核销发票数据量下 ≤ 3 秒 |
| 流水导入处理速度 | ≤ 10 秒 / 100 行 |
| 核销操作响应时间 | ≤ 500 ms |
| 页面加载时间 | ≤ 2 秒 |

### 5.2 易用性

- 核销界面采用 **左右分栏设计**：左侧为银行流水列表，右侧为待选发票列表
- 支持 **拖拽匹配**：将左侧流水拖拽至右侧发票上自动关联
- 支持 **快捷键操作**：
  - `Ctrl+Enter`：确认核销
  - `Ctrl+S`：保存当前选择
  - `Esc`：取消操作
- 支持 **批量操作**：勾选多条流水，批量确认为业务回款

### 5.3 安全性

- 敏感资金数据的传输与存储需加密（HTTPS / AES-256）
- 核销操作属于高风险动作，建议增加 **二次密码验证** 或 **短信验证码校验**
- 出纳无法修改已推送至待认领池的流水数据（FR-04）
- 核销操作需记录完整审计日志（DR-03）
