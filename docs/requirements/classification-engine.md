# 银行流水智能分类规则引擎 · 需求分析

> 版本: v1.0  
> 状态: 评审中

## 1. 项目背景

当前系统已实现基本的银行流水导入和手工分类功能，但存在以下痛点：

1. **分类规则简单**：仅支持单关键词正则匹配，无法处理多条件 AND 组合
2. **执行顺序不严谨**：无明确的规则组瀑布执行，容易误判（如内部转账被误判为业务收款）
3. **缺少排除机制**：无法通过排除词避免误匹配
4. **客商匹配无法联动**：分类阶段未与 CRM 客户/供应商档案联动
5. **置信度缺失**：出纳无法了解分类的可靠程度，需要逐一人工核查
6. **无历史学习**：重复交易对手无法自动继承历史分类

## 2. 业务目标

构建一套完整的银行流水智能分类规则引擎，实现：

- **自动分类率 ≥ 80%**：新导入流水自动匹配规则并完成分类
- **零误判内部转账**：内部转账规则优先级最高，杜绝误判为收付款
- **出纳效率提升**：高置信度分类一键确认，仅低置信度需人工核查
- **规则可配置**：系统管理员可随时调整规则，无需改代码

## 3. 用户角色与权限

| 角色 | 可操作内容 | 权限 |
|------|-----------|------|
| 系统管理员 (setup) | 管理分类规则（增删改查、排序、启停） | 全部 |
| 出纳 (cash) | 查看待处理流水、确认/修改分类结果 | 使用 |
| 会计 (accounting) | 只读查看规则列表 | 只读 |

## 4. 功能需求

### FR-1: 规则组瀑布执行

**描述**：规则按 rule_group 分6组顺序执行，同组内按 priority 排序。命中即停，不再继续。

**验收条件**：
- [ ] 内部转账组（第1组）先于银行费用组（第2组）执行
- [ ] 同一组内 priority 小的先执行
- [ ] 命中一条规则后不再检查后续规则
- [ ] 兜底组（第6组）在所有规则均未命中时生效

### FR-2: 多条件AND匹配

**描述**：每条规则可配置多个条件（方向、对方关键词、摘要关键词、金额范围），全部满足才命中。

**验收条件**：
- [ ] 方向不匹配的直接跳过
- [ ] 对方户名包含所有include关键词且不包含任何exclude关键词
- [ ] 摘要包含所有include关键词且不包含任何exclude关键词  
- [ ] 金额在 [min, max] 范围内（如有配置）
- [ ] 任一条件不满足即不命中

### FR-3: 内部转账识别

**描述**：系统级别最高优先级，防止内部转账被误判为业务收付款。

**判断逻辑**：
- 对方户名包含本企业任一银行账户户名
- OR 对方账号等于本企业任一银行账号
- OR 摘要包含内部转账关键词

**验收条件**：
- [ ] 企业内 A 账户转 B 账户 → 识别为内部转账
- [ ] 活期转定期 → 识别为内部转账
- [ ] 资金归集/下拨 → 识别为内部转账
- [ ] 生成单据类型: 银行转账单

### FR-4: 银行费用识别

**描述**：借方流水，金额通常较小，有明确费用关键词。

**判断逻辑**：
- 方向 = outflow
- 摘要包含费用关键词（手续费、工本费、汇划费等）
- （对方含银行名称 或 对方为空）
- 排除：摘要含"退款"、"退费"
- 排除：金额 > 1万元且无费用关键词

**验收条件**：
- [ ] 转账手续费 → 识别为银行费用
- [ ] 网银年费 → 识别为银行费用  
- [ ] 摘要含"退款手续费" → 不命中（排除词生效）
- [ ] 生成单据类型: 银行费用单

### FR-5: 利息收入识别

**描述**：贷方流水，特征明确。

**判断逻辑**：
- 方向 = inflow
- 摘要包含利息关键词
- AND（对方含银行名称 OR 摘要含"结息"）

**验收条件**：
- [ ] 活期结息 → 识别为利息收入
- [ ] 定期存款利息 → 识别为利息收入
- [ ] 生成单据类型: 利息收入单

### FR-6: 业务收款识别

**描述**：贷方流水，排除利息收入。

**判断逻辑**：
- 方向 = inflow
- 未命中利息规则
- 对方户名匹配系统内客户（精确/模糊≥80%/历史60天）
- OR 摘要包含收款关键词

**验收条件**：
- [ ] 客户"北京华联"来款 → 识别为收款（对方匹配）
- [ ] 摘要"货款/预付款" → 识别为收款（关键词）
- [ ] 陌生对手方但摘要含"结算款" → 推荐为收款（低置信度）
- [ ] 生成单据类型: 收款单

### FR-7: 业务付款识别

**描述**：借方流水，排除银行费用。

**判断逻辑**：
- 方向 = outflow
- 未命中费用规则
- 对方户名匹配系统内供应商（精确/模糊≥80%/历史60天）
- OR 摘要包含付款关键词

**验收条件**：
- [ ] 供应商"深圳万象"付款 → 识别为付款
- [ ] 缴纳税款 → 识别为付款
- [ ] 支付房租 → 识别为付款
- [ ] 工资发放 → 识别为付款
- [ ] 生成单据类型: 付款单

### FR-8: 兜底逻辑

**描述**：以上规则均未命中时归入待处理池。

**验收条件**：
- [ ] 陌生对手方且摘要模糊 → 归入待处理
- [ ] 待处理池中显示相关信息供出纳判断
- [ ] 出纳可手动选择分类并确认

### FR-9: 置信度评估

**描述**：每个分类结果附带置信度百分比，出纳据此决策。

| 置信度 | 颜色 | 建议操作 |
|--------|------|---------|
| ≥80 | 绿色 | 一键确认 |
| 60-79 | 黄色 | 重点核对 |
| <60 | 灰色 | 建议人工判断 |

**验收条件**：
- [ ] 精确匹配客户/供应商 → 置信度 ≥80
- [ ] 模糊匹配客户/供应商 → 置信度 60-79
- [ ] 仅摘要关键词匹配 → 置信度 <60
- [ ] 兜底 → 置信度 0

### FR-10: 历史学习

**描述**：系统自动记录对手方与分类的关联关系，60天内再次出现时自动继承。

**验收条件**：
- [ ] 手工确认分类后记录对手方-分类映射
- [ ] 相同对手方再次出现自动继承历史分类
- [ ] 历史匹配置信度为 80（中等偏高）
- [ ] 超过60天未出现的对手方历史记录失效

### FR-11: 规则管理界面

**描述**：系统管理员可在前端管理所有分类规则。

**页面功能**：
- 规则列表（表格展示规则组、名称、方向、分类、启停状态）
- 规则编辑（弹窗表单配置所有条件）
- 拖拽排序（同组内）
- 启用/禁用开关

### FR-12: 出纳核对界面增强

**描述**：待处理流水池增加辅助决策信息。

**增强内容**：
- 命中规则名称
- 置信度百分比（带颜色标识）
- 一键确认按钮（高置信度快捷操作）
- 原有下拉分类选择保留

## 5. 非功能需求

### NFR-1: 性能
- 单条流水分类耗时 < 50ms
- 批量导入1000条流水分类耗时 < 3s

### NFR-2: 可扩展性
- 新规则类型可通过添加 rule_group 值扩展
- 匹配条件可通过新增列扩展，无需改代码逻辑

### NFR-3: 数据一致性
- 分类操作在数据库事务中完成
- 规则启用/禁用不影响正在执行的分类

## 6. 数据流

```
[导入流水] → [逐条调用分类引擎] → [命中规则?] → 是 → [设置category+business_type] → [是否启用自动生成?] → 是 → [生成单据]
                                              → 否 → [归入待处理池 category=pending]
```

```
[出纳确认分类] → [更新流水category] → [记录CaMatchHistory] → [触发单据生成]
```

## 7. 依赖关系

| 依赖 | 用途 |
|------|------|
| `crm_matching_service` | 客户/供应商模糊匹配 |
| `auto_generate_documents` | 分类后自动生成单据 |
| `CaTransaction.category` | 存储分类结果 |
| `CaClassificationRule` | 规则定义和条件 |

## 8. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 规则误判导致生成错误单据 | 财务数据错误 | 分类仅设置category，不自动生成单据（需人工确认后才生成） |
| 模糊匹配阈值过低 | 误匹配 | 阈值设为80%，可配置 |
| 历史学习累积错误 | 错误继承 | 历史记录可清除，每次手动确认可覆盖 |
