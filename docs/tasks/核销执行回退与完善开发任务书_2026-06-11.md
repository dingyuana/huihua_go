## 任务 1 (P0-1): 核销执行 — 后端 `ExecutePair`

**目标**：`POST /reconciliation/execute` 将confirmed的pair正式核销落库

**文件**：
1. `internal/service/reconciliation_service.go` — 新增 `func (s *ReconciliationService) ExecutePairs(ctx context.Context, tenantID uuid.UUID, pairIDs []uuid.UUID) (*ExecutePairResult, error)`

**Service 方法逻辑**（一个事务）：
```
1. 验证所有pair存在且status=confirmed
2. 对每个pair（遍历）：
   a. 如果 SourceType='bank_txn', TargetType='invoice':
      - INSERT INTO payment_allocations (id, payment_entry_id, invoice_id, invoice_type, allocated_amount, tenant_id, created_at)
        VALUES ($1, $2, $3, 'ar_invoice', $4, $5, $6)
      - UPDATE ar_invoices SET paid_amount = paid_amount + $amount, 
        outstanding_amount = amount - (paid_amount + $amount)
      - UPDATE ar_invoices SET status = CASE WHEN outstanding_amount <= 0 THEN 'paid' ELSE 'partially_paid' END
      - UPDATE bank_transactions SET matched = true WHERE id = $sourceID
      - Update pair status → 'executed'
   b. 如果 SourceType='payment_entry', TargetType='ar_invoice':
      - 同样处理（payment_entry对应的bank_txn也要matched=true）
3. 返回 {executed_count, failed_ids, errors}
```

3. `internal/handler/reconciliation_handler.go` — 新增 `ExecutePairs` handler
4. `cmd/api/main.go` — 注册 `api.Post("/reconciliation/execute", reconciliationHandler.ExecutePairs)`

**注意**：ReconciliationService 已有 paymentEntryRepo（在working tree未commit），让OpenCode检查main.go中的注入是否已添加。如果没加，一并处理。

## 任务 2 (P0-2): 核销回退 — 后端 `ReversePair`

**目标**：`POST /reconciliation/pairs/:id/reverse` 回退已执行的核销

**文件**：
1. `internal/service/reconciliation_service.go` — 新增 `func (s *ReconciliationService) ReversePair(ctx context.Context, tenantID, pairID uuid.UUID) error`

**Service 方法逻辑**（一个事务）：
```
1. 验证pair存在且status=executed
2. 查找对应的 payment_allocations（by pair的SourceID+TargetID）
3. 恢复 ArInvoice amounts：
   - UPDATE ar_invoices SET paid_amount = paid_amount - $amount, 
     outstanding_amount = amount - (paid_amount - $amount)
4. 恢复 ArInvoice status（根据新的outstanding_amount判断）
5. 恢复 bank_transactions matched = false
6. 删除/标记 payment_allocations 为 reversed
7. Update pair status → 'reversed'
```

2. `internal/handler/reconciliation_handler.go` — 新增 `ReversePair` handler
3. `cmd/api/main.go` — 注册 `api.Post("/reconciliation/pairs/:id/reverse", reconciliationHandler.ReversePair)`

## 任务 3 (P1-1): 预检强制通过 — 后端 `ForcePassPreCheck`

**目标**：`POST /reconciliation/precheck/force-pass` 跳过预检创建pair

**文件**：
1. `internal/service/reconciliation_service.go` — 新增 `func (s *ReconciliationService) ForcePassPreCheck(ctx context.Context, tenantID, paymentID, invoiceID uuid.UUID, reason string) (*model.ReconciliationPair, error)`

**逻辑**：
```
1. 验证 payment 和 invoice 存在
2. 不做任何blocked/warning检查
3. 直接创建 pair（status=confirmed），备注记录强制通过原因
4. 返回创建的pair
```

2. `internal/handler/reconciliation_handler.go` — 新增 `ForcePassPreCheck` handler
3. `cmd/api/main.go` — 注册 `api.Post("/reconciliation/precheck/force-pass", reconciliationHandler.ForcePassPreCheck)`

## 任务 4 (P1-2): 月底结转前端完善

### 4-A: 后端 — 新增预览/执行结转端点

**目标**：两个新端点

**文件**：
1. `internal/service/period_service.go` — 新增：
   - `func (s *PeriodService) PreviewClosing(ctx context.Context, tenantID uuid.UUID, periodNo int) (*ClosingPreview, error)`
   - `func (s *PeriodService) ExecuteClosing(ctx context.Context, tenantID uuid.UUID, periodNo int, userID, userName string) (*ClosingResult, error)`

**PreviewClosing 逻辑**：
```
SELECT 收入类科目余额汇总 → income_total
SELECT 费用类科目余额汇总 → expense_total  
profit = income_total - expense_total
返回 {income, expense, profit}
```

**ExecuteClosing 逻辑**：
```
复用 generateClosingEntries 生成结转凭证
返回生成的 voucher_no
不改变 period status（区别于ClosePeriod）
```

2. `internal/handler/period_handler.go` — 新增 PreviewClosing / ExecuteClosing handlers
3. `cmd/api/main.go` — 注册路由：
   - `api.Post("/periods/preview-closing", periodHandler.PreviewClosing)` 
   - `api.Post("/periods/execute-closing", periodHandler.ExecuteClosing)`
