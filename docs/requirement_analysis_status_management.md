# 单据状态管理机制需求分析书

## 1. 需求背景

### 1.1 业务场景描述

在财务系统中，单据（收付款单、发票）与凭证之间存在紧密的关联关系：
- **正向流程**：单据 → 收付款单 → 发票核销 → 凭证生成
- **反向操作**：删除凭证时需回滚关联单据状态

当前系统存在以下问题：
1. 凭证删除时，收付款单状态未同步更新
2. 发票核销状态未随凭证删除而回滚
3. 缺乏统一的状态管理机制

### 1.2 需求目标

建立完整的单据状态管理机制，实现：
- 单据状态的规范流转
- 凭证删除时的反向联动
- 完整的审计日志记录

## 3. 状态机设计

### 3.1 收付款单状态机

**状态定义：**

| 状态值 | 状态名称 | 说明 |
|-------|---------|------|
| 0 | draft | 草稿状态，可编辑可删除 |
| 1 | submitted | 已提交，等待审核 |
| 2 | approved | 已审核，等待生成凭证 |
| 3 | posted | 已过账，已生成凭证 |
| 4 | cancelled | 已作废 |

**状态流转规则：**

```
                    ┌─────────────────────────────────────────────────┐
                    ↓                                                 ↑
    [draft(0)] ──submit──→ [submitted(1)] ──approve──→ [approved(2)] ──generate_voucher──→ [posted(3)]
       │                           │                        │                            │
       │                           │                        │                            │
    cancel                      reject                  cancel                     reverse
       │                           │                        │                            │
       ↓                           ↓                        ↓                            ↓
    [cancelled(4)] ←───────────────←──────────────────────←──────────────────────────────←
```

**状态转换矩阵：**

| 当前状态 | 允许操作 | 目标状态 |
|---------|---------|---------|
| draft | submit | submitted |
| draft | cancel | cancelled |
| submitted | approve | approved |
| submitted | reject | draft |
| approved | generate_voucher | posted |
| approved | cancel | cancelled |
| posted | reverse | cancelled |
| cancelled | - | - |

### 3.2 发票状态机

**状态定义：**

| 状态值 | 状态名称 | 说明 |
|-------|---------|------|
| draft | 草稿 | 可编辑 |
| submitted | 已提交 | 等待审核 |
| verified | 已审核 | 可核销 |
| partially_paid | 部分核销 | 有未核销金额 |
| paid | 已核销 | 全部金额已核销 |
| invalid | 已作废 | 不可用 |

**状态流转规则：**

```
    [draft] ──submit──→ [submitted] ──verify──→ [verified] ──allocate──→ [partially_paid] ──allocate──→ [paid]
       │                      │                    │                           │                           │
       │                      │                    │                           │                           │
    cancel                 reject               cancel                     reverse                    reverse
       │                      │                    │                           │                           │
       ↓                      ↓                    ↓                           ↓                           ↓
    [invalid] ←───────────────←──────────────────←──────────────────────────←──────────────────────────←
```

## 4. 反向联动流程

### 4.1 凭证删除触发的反向联动

**流程说明：**

```
删除凭证
    │
    ▼
┌───────────────────────────────────┐
│ 1. 获取凭证信息                    │
│    - SourceDocType                │
│    - SourceDocID                  │
│    - DocStatus                    │
└───────────────────────────────────┘
    │
    ▼
┌───────────────────────────────────┐
│ 2. 判断是否关联收付款单            │
│    SourceDocType == "payment_entry"│
└───────────────────────────────────┘
    │ 是
    ▼
┌───────────────────────────────────┐
│ 3. 根据凭证状态确定目标状态        │
│    - DocStatus=3 → approved       │
│    - DocStatus=2 → submitted      │
│    - DocStatus=1 → draft          │
└───────────────────────────────────┘
    │
    ▼
┌───────────────────────────────────┐
│ 4. 更新收付款单状态                │
│    - DocStatus = 目标状态          │
│    - VoucherID = NULL             │
│    - VoucherNo = NULL             │
└───────────────────────────────────┘
    │
    ▼
┌───────────────────────────────────┐
│ 5. 回滚发票核销                    │
│    - 恢复 OutstandingAmount       │
│    - 更新发票状态                  │
│    - 删除核销记录                  │
└───────────────────────────────────┘
    │
    ▼
┌───────────────────────────────────┐
│ 6. 记录审计日志                    │
└───────────────────────────────────┘
    │
    ▼
┌───────────────────────────────────┐
│ 7. 删除凭证及凭证行                │
└───────────────────────────────────┘
```

### 4.2 事务边界

所有反向联动操作必须在同一数据库事务中完成，确保原子性：

```
BEGIN TRANSACTION
    │
    ├─ 更新收付款单状态
    │
    ├─ 回滚发票核销
    │
    ├─ 记录审计日志
    │
    └─ 删除凭证
    │
COMMIT / ROLLBACK
```

## 5. 数据一致性保障

### 5.1 约束规则

| 约束编号 | 约束描述 | 实现方式 |
|---------|---------|---------|
| CON-001 | 只有draft状态的收付款单可编辑 | 状态机校验 |
| CON-002 | 只有approved状态的收付款单可生成凭证 | 状态机校验 |
| CON-003 | 只有未生成凭证的收付款单可取消 | 状态机校验 |
| CON-004 | 删除凭证时必须先回滚关联单据 | 事务保障 |
| CON-005 | 发票核销金额不能超过未核销金额 | 业务逻辑校验 |

### 5.2 异常处理

| 异常场景 | 处理策略 |
|---------|---------|
| 收付款单不存在 | 返回错误，事务回滚 |
| 发票不存在 | 跳过该发票，继续处理其他发票 |
| 更新失败 | 事务回滚，返回错误信息 |
| 并发冲突 | 使用乐观锁，返回冲突错误 |

## 7. 接口设计

### 7.1 收付款单状态变更接口

**POST /api/v1/payments/{id}/status**

请求体：
```json
{
    "action": "submit",
    "user_id": "uuid",
    "user_name": "string",
    "reason": "optional string"
}
```

响应体：
```json
{
    "success": true,
    "payment_id": "uuid",
    "previous_status": 0,
    "new_status": 1,
    "message": "status updated successfully"
}
```

### 7.2 凭证删除接口

**DELETE /api/v1/vouchers/{id}**

请求参数：
- id: 凭证ID

响应体：
```json
{
    "success": true,
    "voucher_id": "uuid",
    "rollback_payment": {
        "payment_id": "uuid",
        "previous_status": 3,
        "new_status": 2
    },
    "rollback_invoices": [
        {
            "invoice_id": "uuid",
            "previous_outstanding": "100.00",
            "new_outstanding": "200.00",
            "previous_status": "paid",
            "new_status": "partially_paid"
        }
    ]
}
```

## 10. 风险评估

| 风险 | 描述 | 缓解措施 |
|------|------|---------|
| 数据一致性 | 删除凭证时可能部分成功部分失败 | 使用数据库事务确保原子性 |
| 性能影响 | 大量发票核销回滚可能耗时 | 批量操作优化，异步处理 |
| 并发冲突 | 同时删除凭证和修改收付款单 | 使用乐观锁或悲观锁 |
| 状态不一致 | 手动修改数据库导致状态混乱 | 添加状态校验，禁止非法状态 |
