## 修复项（已修复）

### 1-1. CRITICAL: ReversePair 回退 ar_invoice 时写入了非法状态 'verified'
**文件：** `internal/service/reconciliation_service.go:742,744`
**问题：** `ReversePair` 回退 ar_invoice 金额时，SQL 中写死了 `status = 'verified'`，但 `ArInvoiceStatus` 模型中无此值（合法值：draft/confirmed/partially_paid/paid/reversed/overdue）。
**影响：** 回退后 DB 写入无效状态，前端枚举映射不到、查询过滤失效。
**对比：** 同文件中 `ap_invoice` 回退（第728行）正确使用了 `'confirmed'`。
**修复：** `'verified'` → `'confirmed'` ✅ 已提交 ac00ed11

### 3. DESIGN GAP: 自动匹配后的「确认」路径断裂
**入口：** `POST /reconciliation/run`（自动匹配）
**涉及函数：** `Reconcile()` → `makePair()` → `Create()`
**现状：** 自动匹配生成 `status="matched"` 的 pair，持久化到 DB。
**问题：** 
- `ConfirmPair` repo 方法（`POST /reconciliation/pairs/:id/confirm`）只接受 `status="pending"` 的 pair
- `ExecutePairs` 只接受 `status="confirmed"` 的 pair
- 自动匹配产生的 pair 卡在 `matched` 状态，无法通过任何接口推进到 `confirmed` → `executed`

**绕行方式：**
- 手工核销（`ManualMatch`）直接创建 `confirmed` pair，不走确认流程
- 强制通过（`ForcePass`）同样直接创建 `confirmed` pair
- 所以实际业务流程中用户从未真正使用过自动匹配的确认通道

**建议修复：** 提供接口将 `matched` → `confirmed`（可直接在 `ConfirmPair` service 层增加对 `matched` 状态的兼容）

---

### 4. DESIGN GAP: 自动匹配不标记 bank_txn 为已匹配
**文件：** `internal/service/reconciliation_service.go` `Reconcile()`
**对比：** `ManualMatch()` 创建 pair 后调 `bankTxnRepo.UpdateMatched(ctx, ..., true)`，自动匹配不调。
**问题：** 
- `ListUnmatched / GetUnmatched` 按 `matched = FALSE` 过滤 → 自动匹配过的 bank_txn 仍会被返回
- 自动匹配的 `Reconcile()` 内部用 in-memory `matchedBank` map 防重复，但跨次调用时同一 bank_txn 可能反复生成相同的 pair

**建议：** 自动匹配 pair 创建后也应标记 bank_txn `matched = true`

### 6. 完整业务流程状态图

```
┌─────────────────────────────────────────────────────────────┐
│  核销流程完整状态图（三大入口 → 统一出口）                    │
└─────────────────────────────────────────────────────────────┘

入口A：自动匹配
  POST /reconciliation/run
  bank_txn(未标记matched) + invoice(verified/partially_paid)
    → pair.status = matched
    → ⚠️ 无法推进 → 断裂（见第3项）

入口B：手工核销
  POST /reconciliation/manual  
  bank_txn(选择) + invoice(选择) + 金额
    → pair.status = confirmed  (直接跳过确认)
    → bank_txn.matched = true

入口C：强制通过  
  POST /reconciliation/precheck/force-pass
  PreCheck → 仅warning可强制
    → pair.status = confirmed (直接跳过确认)
    → bank_txn.matched = true

出口1：执行核销
  POST /reconciliation/execute  
  pair.status: confirmed → executed
  ar_invoice: paid_amount+=, outstanding-=, status→paid/partially_paid
  bank_txn: matched=true (若source_type=bank_txn)
  payment_allocations: INSERT (若source_type≠bank_txn)

出口2：回退核销
  POST /reconciliation/pairs/:id/reverse
  pair.status: executed → reversed
  ar_invoice: paid_amount-=, outstanding+=, status→confirmed/partially_paid
  bank_txn: matched=false (若source_type=bank_txn)
  payment_allocations: reversed_at=NOW() (若有)
```
