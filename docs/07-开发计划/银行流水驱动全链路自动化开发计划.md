## 一、项目范围与目标

### 1.1 范围界定

本计划覆盖 `docs/02-需求分析/业财一体化银行流水驱动模块需求分析.md` V2.0定义的八个模块：

| 模块 | 说明 |
|---|---|
| 模块一：基础数据与规则引擎 | 银行账户/模板管理、智能分类规则库、科目映射规则 |
| 模块二：银行流水导入与智能分类 | 六类分类（收款单/付款单/银行费用单/利息收入单/银行转账单/待处理）、待处理流水池 |
| 模块三：业务单据管理 | 六种标准单据的生成与状态管理、现金单据（人工录入） |
| 模块四：发票核销管理 | 自动核销引擎、容差处理、手工核销中心、状态联动 |
| 模块五：银企对账 | 自动对账、余额调节表、手工强制对账 |
| 模块六：现金管理 | 现金日记账、现金盘点差异报告 |
| 模块七：凭证生成与总账接口 | 凭证模板、批量生成、双向联查、红蓝字冲销 |
| 模块八：常用凭证模板 | 六种单据的标准借贷分录定义 |

**不包含在本计划内：**
- 发票的CRUD（录入/查重/红冲）由F03/F04模块管理，本计划只做匹配和关联
- 凭证审核/过账/冲红由F01模块管理，本计划只负责生成
- 结账流程由期末结账spec管理，本计划生成的凭证参与结账

### 1.2 核心目标

以银行流水为唯一驱动源，实现：
1. 流水智能分类（六类：收/付/费用/利息/转账/待处理）
2. 业务单据自动生成 + 发票智能匹配 + 自动核销
3. 银企自动对账 + 余额调节表
4. 凭证批量生成（全链路可追溯）
5. 现金管理（日记账 + 盘点）
6. 红蓝字冲销机制

#### P0.2：合并双重 db.commit()

**文件：** `backend/app/api/v1/cash.py`（import API）

**现状问题：**
```python
# 第一阶段：流水入库
db.commit()
# 第二阶段：生成收付款单
gen_result = auto_generate_documents(db, imported_txns, current_user)
db.commit()  # ← 第二阶段独立commit
```

**改为：**
```python
# 所有操作在一个事务内
db.commit()  # 一次性提交流水+单据
```

**改动点：**
1. 第一次 commit 后，imported_txns 已在 session 中
2. `auto_generate_documents` 使用 `db.flush()` 而非自行 commit
3. 调用方统一一次 commit

**验收标准：**
- [ ] 导入过程中抛异常时，全部回滚，无脏数据
- [ ] 导入成功后，流水和收付款单同时存在

#### P0.3：厘清发票号体系

**决策：** ArInvoice.invoice_no = InvoiceIssue.invoice_number（一对一绑定）

**当前状态确认：**
- `InvoiceIssue.invoice_number` 是税务系统真实发票号（数电发票号）
- `ArInvoice.invoice_no` 是应收发票编号，当前与 InvoiceIssue 独立
- 需求分析书确认：两者一对一绑定，ArInvoice.invoice_no = InvoiceIssue.invoice_number

**影响分析：**
- BusReceipt.invoice_no 后续关联到 ArInvoice.invoice_no（税务发票号）
- 核销联动时，通过 ArInvoice.invoice_no 追溯到 InvoiceIssue.invoice_number

**需要修改：** 无代码改动，只需在开发计划中记录此设计决策
