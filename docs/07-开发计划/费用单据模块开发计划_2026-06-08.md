## 二、TASK-2.5 销售发票增强（P1）

**目标**：增强 SalesInvoice 模型，支持数电发票字段、部分红冲功能，补齐与需求分析书V6.1第十四章的差距。

### 2.5.1 新增字段（10个）

`invoice_kind / electronic_url / red_letter_info_id / red_letter_reason / original_invoice_id / is_part_red / red_amount / tax_authority_code / confirm_status / confirm_date`

### 2.5.2 新增API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/invoices/sales/{id}/confirm` | 确认销售发票 |
| POST | `/invoices/sales/{id}/red` | 红冲 |
| POST | `/invoices/sales/{id}/red/part` | 部分红冲 |
| POST | `/invoices/sales/{id}/void` | 作废 |

### 2.5.3 凭证规则

- 正常：借 应收账款 / 贷 主营收入+销项税
- 红冲：借贷方向红字
- 部分红冲：按red_amount比例红字

**任务文档**：`docs/tasks/TASK-2.5-sales-invoice-enhance.md`

## 三、TASK-2.6 费用报销单增强（P0）

**目标**：完善 BusReimbursement 三大缺失（附件上传/驳回持久化/发票关联）。

### 2.6.1 附件实际上传

- 新建 `reimbursement_attachments` 表
- API：GET/POST/DELETE /reimbursements/{id}/attachments
- 存储路径：`uploads/attachments/{reimbursement_no}/`
- 格式：jpg/png/pdf，≤10MB

### 2.6.2 驳回原因持久化

- 修改 Reject service：将 reason 参数写入 DB
- `reject_reason` 字段已存在模型，需落地存储

### 2.6.3 进项发票关联

- 新建 `reimbursement_invoice_links` 表
- API：GET/POST/DELETE /reimbursements/{id}/invoices
- 支持部分金额关联（发票金额 > 报销金额时）

### 2.6.4 费用类型细分

- 扩展为8种：travel/office/entertain/transport/communication/training/welfare/other
- 新增 `sub_expense_type` 子类型字段

### 2.6.5 凭证生成规则

按费用类型映射科目（借6602.x管理费用/贷银行存款）

**任务文档**：`docs/tasks/TASK-2.6-reimbursement-enhance.md`
