## 一、现状问题汇总

### 1.1 银行流水导入逻辑问题

| 问题 | 位置 | 影响 |
|------|------|------|
| auto_generate_documents 中自动设置 is_reconciled=True | cash_service.py | 出纳失去对账操作环节 |
| 双重 db.commit() | cash.py import API | 事务边界不清晰，第二阶段失败则数据不一致 |
| 收付款单操作入口被移除 | 前端 ReceiptList.vue / PaymentList.vue | 会计无法直接从列表页操作 |
| 银行账户余额（CaBank.balance）与凭证过账不联动 | 缺少触发逻辑 | CaBank.balance 只能手动维护 |

### 1.2 发票关联问题

| 问题 | 位置 | 影响 |
|------|------|------|
| BusReceipt.invoice_id 有 FK 但大量 NULL | business.py | 无法关联发票 |
| 收付款单无发票号码文本字段 | bus_receipt / bus_payment | 展示/打印无发票号 |
| 发票匹配能力缺失 | 无 service | 只能手动选择，无法智能推荐 |
| 两套发票号体系未厘清 | ArInvoice.invoice_no vs InvoiceIssue.invoice_number | 关联逻辑混乱 |

### 1.3 企业日记账（CaCashJournal）问题

| 问题 | 位置 | 影响 |
|------|------|------|
| 现金日记账与银行流水双向关联已建立，但业务场景未完整定义 | cash.py | 提现/存现场景已通，但一般收款/付款场景未覆盖 |
| 现金日记账不参与收付款单流程 | 独立于 auto_generate_documents | 银行流水收款后，现金日记账无对应记录 |
| 现金日记账和收付款单的联动关系未定义 | 缺少 service | 无法确认企业日记账在本流程中的位置 |

### 1.4 关键数据模型确认

```
InvoiceIssue.invoice_number  → 税务系统真实发票号（数电发票号）
ArInvoice.invoice_no         → 应收发票记录编号（应与 invoice_number 一致或关联）
ApInvoice.invoice_no         → 应付发票记录编号

BusReceipt.invoice_id        → FK → ar_invoice.id（关联应收账款记录，已有但大量NULL）
BusReceipt.invoice_no        → 缺失，需新增（varchar，发票号文本）
BusPayment 同上
```

## 二、目标业务流程

```
出纳：上传银行流水 CSV/XLSX
  ↓
解析入库（CaTransaction，is_reconciled=False）
  ↓
出纳：对账操作（勾选确认这笔流水真实到账）
  ├─ 方式A：逐笔对账（列表勾选）
  └─ 方式B：批量对账（全选确认）
  ↓
系统：根据对账流水自动生成收付款单（BusReceipt/BusPayment，status=draft）
  ↓
出纳/会计：对收付款单补充信息
  ├─ 确认客户/供应商
  ├─ 智能匹配发票（推荐可核销发票）← 新增
  ├─ 关联发票号（手动选择 / 自动带入）← 新增
  └─ 确认完成（status → confirmed）
  ↓
会计：生成凭证（过账）→ 更新 AccAccount 余额
  ↓
发票核销联动
  ├─ 收款单完成 → 自动核销 ArInvoice.balance_amount
  └─ 付款单完成 → 自动核销 ApInvoice.balance_amount
  ↓
企业日记账联动（CaCashJournal）
  ├─ 场景1：银行收款 → CaTransaction.inflow → 现金日记账收入记录
  ├─ 场景2：银行付款 → CaTransaction.outflow → 现金日记账支出记录
  └─ 场景3：提现/存现 → 双向联动（已有）
```

## 三、整体架构设计

### 3.1 核心实体关系

```
CaBank (银行账户)
  ↓ has many
CaTransaction (资金流水)
  ├─ is_reconciled: bool（出纳对账标志）
  ├─ linked: CaDocLink → BusReceipt / BusPayment
  └─ source_transaction_id → CaCashJournal（提现/存现双向联动）

BusReceipt (收款单)
  ├─ invoice_id → ArInvoice（FK，已有但大量NULL）
  ├─ invoice_no → 新增（varchar，发票号文本）
  ├─ voucher_id → AccVoucher（FK，已有）
  └─ linked: CaDocLink ← CaTransaction

BusPayment (付款单)
  ├─ invoice_id → ApInvoice（FK，已有但大量NULL）
  ├─ invoice_no → 新增（varchar，发票号文本）
  ├─ voucher_id → AccVoucher（FK，已有）
  └─ linked: CaDocLink ← CaTransaction

ArInvoice (应收账款)
  ├─ invoice_no → 应收发票编号
  ├─ balance_amount → 未核销金额
  ├─ status: paid/unpaid/partial
  └─ writeoff_amount → 已核销金额

CaCashJournal (现金日记账)
  ├─ source_transaction_id → CaTransaction（提现时）
  └─ balance_after → 现金余额
```

### 3.2 发票匹配逻辑

智能匹配规则（invoice_matching_service.py）：

| 优先级 | 匹配条件 | 匹配置信度 |
|--------|---------|-----------|
| 1 | 金额完全一致 + 客户名称精确匹配 + 日期在合理窗口内（±30天） | 高 |
| 2 | 金额完全一致 + 客户名称模糊匹配（相似度>0.7） | 中 |
| 3 | 金额在±5%范围 + 客户名称精确匹配 | 中低 |
| 4 | 客户名称精确匹配 + 日期在合理窗口内（金额不限） | 低（供人工参考） |

匹配流程：
1. 收款单选择客户ID后，加载该客户所有未核销 ArInvoice
2. 按日期倒序排列，推荐最接近当前收付款日期的发票
3. 用户选择要关联的发票，确认后写入 invoice_id
4. 同时将 ArInvoice.invoice_no 填充到 invoice_no

### 3.3 发票核销联动

收款单确认（status → confirmed）触发：
1. 查找 BusReceipt.invoice_id 对应的 ArInvoice
2. 计算核销金额 = min(BusReceipt.amount, ArInvoice.balance_amount)
3. 更新 ArInvoice：
   - writeoff_amount += 核销金额
   - balance_amount -= 核销金额
   - 若 balance_amount == 0 → status = paid
4. 插入 ArWriteoff + ArWriteoffDetail 核销记录
5. 若 BusReceipt 同时有关联的 CaTransaction → 标记 CaTransaction.is_reconciled = True

付款单确认触发同理（ApInvoice 体系）

- 文件：backend/app/api/v1/cash.py

- 文件：frontend/src/pages/business/ReceiptList.vue / PaymentList.vue

### Phase 3：完整业务流程闭环（预计 2~3 天）

#### P3.1：发票核销联动
- 文件：backend/app/services/invoice_receivable_service.py（新建）
- 文件：backend/app/services/invoice_payable_service.py（新建）
- 核心函数：
  - auto_writeoff_ar_invoice(db, receipt, current_user) -> dict
  - auto_writeoff_ap_invoice(db, payment, current_user) -> dict
- 触发时机：BusReceipt / BusPayment 状态变为 confirmed 时调用

#### P3.2：企业日记账联动
- 问题：企业日记账（CaCashJournal）在整个流程中扮演什么角色？
- 分析：
  - 现状：提现/存现时自动双向联动（已有）
  - 缺口：一般银行收款/付款后，CaCashJournal 无联动记录
- 待定义场景：
  - 场景A：企业同时管理现金和银行存款 → 银行流水入账时同步更新现金日记账
  - 场景B：企业仅管理银行存款 → CaCashJournal 可以简化或跳过
- 建议：采用场景A，在 auto_generate_documents 中同时生成 CaCashJournal 记录

#### P3.3：CaBank.balance 联动确认
- 问题：银行账户余额（CaBank.balance）是否需要在凭证过账时联动更新？
- 现状分析：
  - CaBank.balance 在 create_transaction() 时更新
  - 凭证过账更新 AccAccount（账套级别科目余额）
  - 两者各自独立维护
- 建议：保持分离，CaBank.balance 由出纳通过银行流水维护；AccAccount 由会计通过凭证维护；银行对账功能负责核对两者差异

#### P3.4：前端完整流程 UI
- 收款单/付款单详情页显示关联发票信息
- 收款单/付款单状态流转展示（draft → confirmed → posted）
- 企业日记账页面（CaCashJournal）展示收支明细
