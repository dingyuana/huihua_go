```
│  [一键执行折旧]  [扫描往来款]  [查看异常报告]             │
└──────────────────────────────────────────────────────────┘
```

**原则**：
- 步骤卡片式展示，已完成 ✅ 绿色 / 当前 🔄 蓝色高亮 / 未完成 ⬜ 灰色
- **不可跳过**：上一步未完成，下一步按钮禁用
- **异常必处理**：红色预警项存在，"下一步" 按钮永久置灰
- 点击已完成步骤 → 查看该步骤详情（只读快照）
- 顶部显示当前账套名称 + 会计期间，**支持账套切换下拉**（代账公司场景）

**后端 API 设计**：

| 功能 | 接口 | 返回字段 |
|---|---|---|
| 凭证统计 | `GET /accounting/period/{year}/{month}/pre-close-check` | `voucher_counts`（按状态统计） |
| 断号检测 | 同上 | `voucher_continuity.has_gaps` + `voucher_continuity.items` |
| 附件缺失检测 | `GET /accounting/vouchers?attachment_missing=true` | 缺少附件的凭证列表 |

**附件校验逻辑**：
- 凭证 `attachment_count > 0` 但实际无附件记录 → 标记异常
- 特定类型凭证（如工资表）要求必须有关联附件
- 前端：`v-if="!item.hasAttachment"` 红色高亮显示缺失项

**银行余额调节表数据结构**（前端展示用）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `book_balance` | decimal | 账面余额（`acc_account` 货币资金科目期末余额） |
| `bank_balance` | decimal | 银行对账单余额（用户手工录入或 CSV 导入） |
| `difference` | decimal | 差额 |
| `unreconciled_items` | array | 未达账项列表 |
| `reconciliation_status` | enum | `balanced` / `unbalanced` / `pending` |

**新增 API**：

| 功能 | 接口 | 说明 |
|---|---|---|
| 银行余额调节表查询/新建 | `GET/POST /cash/banks/{bank_id}/reconciliation` | 账面 vs 银行差额 |
| 录入对账单余额 | `POST /cash/banks/{bank_id}/statement` | 导入对账单 |
| 查询未达账项 | `GET /cash/banks/{bank_id}/unreconciled` | 企业已付银行未付 / 企业已收银行未收 |

## 四、技术约束

1. **不新增破坏性依赖**：前端不引入新的 npm 包（html2pdf 除外），后端不引入新的 pip 包
2. **不修改凭证状态机**：结账锁定逻辑不改变
3. **不修改历史数据**：结账后的数据只能通过调账凭证修正，不可直接修改
4. **向后兼容**：所有 API 变更均为追加，不删除已有字段
5. **账套隔离**：所有操作按 `company_id` 隔离，多账套场景下数据互不可见
