# Phase 1 TRIAGE — 高频业务单据 & 自动凭证映射

## 需求摘要

慧话财务当前只有手工凭证入口，缺了会计日常使用的**三类高频业务单据**：费用报销单、收款单、付款单。会计做账的逻辑是"先有单据再生成凭证"，目前只能直接录凭证，缺少业务层。

## 识别到的约束

1. **单账套架构**：所有单据属于当前账套，不引入多账套概念
2. **复用现有凭证框架**：单据生成凭证调用已有的 `create_voucher_core()`，不重新造凭证引擎
3. **不修改现有凭证状态机**：单据生成的凭证和手工凭证共享同一套状态流转
4. **附件上传复用现有能力**：直接复用文件上传接口
5. **不引入新依赖**：前端只用 Element Plus 现有组件

## 假设

- 会计填完单据后点击"生成凭证"的行为是一次性操作，不涉及草稿多次编辑
- 单据→凭证的科目映射规则默认写死在代码中，Phase 1.3提供自定义配置界面
- 收款单自动关联应收账款科目，付款单自动关联应付账款科目，费用报销单按费用类型匹配

## 依赖

- 无（但依赖前端 `request.js`、后端 `create_voucher_core()` 等现有基础设施）
- 费用报销单用到部门列表（已有 `sys_dept` 表）
