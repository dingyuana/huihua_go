# 期末结转标准规范（销售型企业适用）

> 版本：v1.0
> 日期：2025-05-25
> 适用：销售型/商贸企业（单账套），排除代理记账多账户场景，排除生产型企业（进销存/制造业）

---

## 一、规范范围

本规范定义销售型企业在期末结账前必须执行的检查项目，共7大模块（第〇步~第七步）。每项检查必须通过方可执行结账操作。

**排除范围：**
- 代理记账公司多账户场景（暂不适用）
- 生产型企业（进销存/制造/委外加工）
- 现金流量表自动编制（后续版本）

## 三、阻断规则

以下检查项为**阻断性**（不通过则禁止结账）：

| 步骤 | 检查项 | 阻断条件 |
|------|--------|---------|
| Step0 | 未记账凭证 | `unposted_vouchers > 0` |
| Step0 | 凭证断号 | `voucher_continuity.has_gaps === true` |
| Step1 | 银行对账未完成 | 存在有流水但未对账的银行账户 |
| Step2 | 折旧未计提 | `depreciation_check.checked === false` 或 `unrecorded_assets > 0` |
| Step3 | 税金未核准 | `tax_accrual.all_matched !== true` |
| Step6 | 存在 error 级风险预警 | `risk_warnings` 中有 `severity === 'error'` 且未确认 |
| Step6 | 试算不平衡 | `report_balance_ok === false` |
| Step6 | 损益未结转 | `profit_loss_done === false` |

## 四、前端状态展示规范

前端按以下规则展示每个检查项的状态：

| 状态类型 | 展示文案 | 条件 |
|---------|---------|------|
| ✅ 已完成 | "已完成" / "一致" / "通过" | `passed === true` 或值符合预期 |
| ✅ 已审核通过 | "已审核通过" / "一致" | 无异常数据时 |
| ⚠️ 无数据 | "本期无数据，无需审核" | `checked === false` 且业务逻辑上本期确实无此项 |
| ❌ 未通过 | "未通过：{具体原因}" | `passed === false` 或有错误级别问题 |
| ⏳ 进行中 | "进行中" / "待处理" | 当前步骤未执行完毕 |
| — | "不适用" | 当前范围外（如进销存相关项） |

**用户可读的失败原因格式示例：**
```
❌ 未通过：还有 3 张凭证尚未记账
❌ 未通过：存在 2 处凭证断号（第35号、第36号缺失）
❌ 未通过：工商银行账户有 5 笔流水未对账
❌ 未通过：固定资产折旧尚未计提（2 项使用中资产）
❌ 未通过：税金计提工作流未核准（待财务经理审批）
```
