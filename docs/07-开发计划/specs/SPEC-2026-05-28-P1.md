## 1 背景与目标

### 1.1 问题现状

| # | 问题 | 现状 | 影响 |
|---|---|---|---|
| P1-B1 | 收付款单无发票号文本字段 | BusReceipt/BusPayment 无 invoice_no | 打印/展示无发票号 |
| P1-B2 | 发票匹配全靠手工 | 无智能推荐 | 效率低、易出错 |
| P1-B3 | 核销联动缺失 | ArInvoice.balance_amount 不随收付款更新 | 往来余额不准确 |
| P1-B4 | 无手工核销中心 | 复杂核销（如多对多）无法处理 | 核销不完整 |

### 1.2 目标

实现收付款单与发票的智能匹配 + 自动核销联动，打通"流水→收付款单→发票→核销"链路。

### 2.3 核销联动服务（P1.3）

**文件：** `backend/app/services/invoice_receivable_writeoff.py`（新建）
**文件：** `backend/app/services/invoice_payable_writeoff.py`（新建）

**核心函数（应收）：**

```python
def auto_writeoff_ar_invoice(
    db: Session,
    receipt_id: str,
    current_user,
    force_invoice_id: Optional[str] = None
) -> dict:
    """
    收款单确认时自动核销应收发票。
    
    流程：
    1. 获取 BusReceipt（包含 customer_id, amount, invoice_id）
    2. 若 force_invoice_id 指定，直接用该发票
       否则，用 receipt.invoice_id 或匹配置信度最高的推荐发票
    3. 获取 ArInvoice.balance_amount
    4. 计算核销金额 = min(BusReceipt.amount, ArInvoice.balance_amount)
    5. 更新 ArInvoice：
       - writeoff_amount += 核销金额
       - balance_amount -= 核销金额
       - 若 balance_amount == 0 → status = "paid"
    6. 插入 ArWriteoff（核销主记录）
    7. 插入 ArWriteoffDetail（本次核销明细）
    8. 返回 {success: bool, writeoff_id, amount_written_off, invoice_status}
    
    边界处理：
    - receipt.amount > invoice.balance_amount → 部分核销，invoice余额清零
    - receipt.amount < invoice.balance_amount → 全额核销，receipt完成
    - 无可匹配发票 → 返回 {success: false, reason: "no_matching_invoice"}
    """
```

**核心函数（应付）：**
同上，使用 ApInvoice / ApWriteoff / ApWriteoffDetail 体系。

### 2.4 收付款单确认触发核销（P1.4）

**文件：** `backend/app/api/v1/business.py` 或 `receivable.py` / `payable.py`

**修改点：** 收付款单 status 从 draft → confirmed 时，自动调用核销服务。

```python
# 示例：确认收款单
@router.put("/receipts/{receipt_id}/confirm")
async def confirm_receipt(receipt_id: str, ...):
    receipt = db.query(BusReceipt).filter(BusReceipt.id == receipt_id).first()
    
    # 原有确认逻辑...
    receipt.status = "confirmed"
    receipt.confirmed_at = datetime.now()
    receipt.confirmed_by = current_user.id
    
    # 新增：触发自动核销
    writeoff_result = auto_writeoff_ar_invoice(db, receipt_id, current_user)
    
    # 如果有invoice，填充invoice_no
    if receipt.invoice_id:
        invoice = db.query(ArInvoice).filter(ArInvoice.id == receipt.invoice_id).first()
        if invoice:
            receipt.invoice_no = invoice.invoice_no
    
    db.commit()
    
    return {"receipt": receipt, "writeoff": writeoff_result}
```

**注意：** 核销失败（如无匹配发票）不应阻断确认操作，记录警告即可。

## 3 数据流与状态机

### 3.1 收付款单状态流转

```
draft → confirmed → posted
         ↓
      （自动触发核销）
         ↓
      invoice_id 填充
      invoice_no 填充
      ArInvoice.balance_amount 更新
```

### 3.2 发票核销状态

```
ArInvoice.status: unpaid → partial → paid
ArInvoice.balance_amount: 原始金额 → 逐步扣减 → 0
```

## 5 技术约束

- 不修改 ArInvoice / ApInvoice 模型结构
- 核销联动使用现有事务，不引入分布式事务
- 并发控制：使用 `with_for_update()` 锁行（凭证过账已有，待扩展到核销）
