## 二、P0/P1 任务分解

### P0-1: 核销执行 `POST /reconciliation/execute`

**问题**：`ConfirmPair` 只把pair状态改为"confirmed"，不落 payment_allocations、不更新发票金额。用户确认配对后，核销实际上未生效。

**解法**：新增 `ExecutePair` 方法 + `POST /reconciliation/execute` 端点。

- 输入：`{"pair_ids": ["uuid1", "uuid2"]}`（批量执行）
- 一个事务完成：
  1. 检查pair都是confirmed状态（非confirmed拒绝）
  2. 写入 payment_allocations（payment_entry_id, invoice_id, invoice_type='ar_invoice', allocated_amount）
  3. 更新 ArInvoice paid_amount += amount, outstanding_amount = amount - (paid + amount)
  4. 更新 ArInvoice status → 'paid' (outstanding≤0) / 'partially_paid' (>0)
  5. 更新 pair status → 'executed'
- 返回 executed_count + 失败的pair_ids

**涉及文件**：
- `internal/service/reconciliation_service.go` — ExecutePair 方法
- `internal/handler/reconciliation_handler.go` — ExecutePair handler
- `cmd/api/main.go` — 注册路由
- `frontend/src/api/modules/reconciliation.ts` — 前端API
- `frontend/src/views/reconciliation/PendingConfirmView.vue` — 确认后自动触发执行

### P0-2: 核销回退 `POST /reconciliation/:id/reverse`

**问题**：核销执行后不可逆，没有回退机制。

**解法**：新增 `ReversePair` 方法 + `POST /reconciliation/pairs/:id/reverse` 端点。

- 一个事务完成：
  1. 检查pair是executed状态（非executed拒绝）
  2. 删除/标记 payment_allocations 为 reversed
  3. 恢复 ArInvoice paid_amount -= amount, outstanding_amount = amount - (paid - amount)
  4. 恢复 ArInvoice status（根据新的outstanding_amount）
  5. 更新 pair status → 'reversed'
- 前端：在执行页面加"回退"按钮，确认弹窗

**涉及文件**：
- `internal/service/reconciliation_service.go` — ReversePair 方法
- `internal/handler/reconciliation_handler.go` — ReversePair handler
- `cmd/api/main.go` — 注册路由
- `frontend/src/api/modules/reconciliation.ts` — 前端API
- `frontend/src/views/reconciliation/PendingConfirmView.vue` — 回退按钮

### P1-1: 预检强制通过 `POST /reconciliation/precheck/force-pass`

**问题**：PreCheck 发现 blocked 项目时，用户无法强制跳过（比如明知客户名不一致但确认无误）。

**解法**：新增 `ForcePassPreCheck` 方法 + `POST /reconciliation/precheck/force-pass` 端点。

- 输入：`{"payment_id": "uuid", "invoice_id": "uuid", "reason": "人工确认无误"}`
- 跳过所有 blocked/warning 检查，直接创建 pair（status=confirmed）
- 记录强制通过的原因到 pair 的备注字段
- 前端：PreCheckView.vue 的拒绝按钮旁边加"强制通过"按钮+弹窗输入原因

**涉及文件**：
- `internal/service/reconciliation_service.go` — ForcePassPreCheck 方法
- `internal/handler/reconciliation_handler.go` — ForcePassPreCheck handler
- `cmd/api/main.go` — 注册路由
- `frontend/src/api/modules/reconciliation.ts` — 前端API
- `frontend/src/views/reconciliation/PreCheckView.vue` — 强制通过按钮+弹窗

### P1-2: 月底结转前端完善

**问题**：`previewClosing()` 和 `executeClosing()` 都是硬编码mock，未调用后端真实API。

**解法**：
1. `previewClosing()` → 调后端 `POST /periods/:period_no/preview-closing`（新增端点），返回预览数据（收入/费用/利润金额）
2. `executeClosing()` → 调后端 `POST /periods/:period_no/execute-closing`（新增端点），执行损益结转，返回生成凭证号

**注意**：后端当前 ClosePeriod 的 `generateClosingEntries` 生成结转凭证。新的 preview-closing 端点需要只预览不落库（SELECT 汇总损益科目余额），execute-closing 端点需要只做损益结转不改 period 状态（区别于 ClosePeriod 的全面结账）。

**涉及文件**：
- `internal/service/period_service.go` — PreviewClosing / ExecuteClosing 方法
- `internal/handler/period_handler.go` — PreviewClosing / ExecuteClosing handler
- `cmd/api/main.go` — 注册路由
- `frontend/src/api/modules/period.ts` — 前端API
- `frontend/src/views/period/HealthCheck.vue` — 改用真实API
