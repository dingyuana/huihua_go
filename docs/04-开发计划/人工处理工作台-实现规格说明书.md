## 三、API 设计

### 3.1 客户/供应商查找

```
GET /api/v1/parties/search?q=关键词&type=customer|supplier
Response: { data: [{ id, name, tax_id, ... }] }
```

### 3.2 未核销发票查询

```
GET /api/v1/invoices/unmatched?party_id=<uuid>&type=sale|purchase
Response: { data: [{ id, invoice_no, amount, unmatched_amount, date, ... }] }
```

### 3.3 人工生成收款单

```
POST /api/v1/manual/receipt
Body: {
  bank_transaction_id: "uuid",
  party_id: "uuid",
  payment_nature: "goods_payment|pre_receipt|deposit|...",
  allocations: [{ invoice_id: "uuid", amount: 1000.00 }],
  tolerance_amount: 2.50,
  posting_date: "2026-06-02"
}
Response: {
  payment_entry: { id, payment_no, ... },
  voucher: { id, voucher_no, ... } | null
}
```

### 3.4 人工生成付款单

```
POST /api/v1/manual/payment
Body: (同上，payment_nature 不同选项)
Response: { payment_entry, voucher }
```

### 3.5 人工直接生成凭证

```
POST /api/v1/manual/voucher
Body: {
  bank_transaction_id: "uuid",
  business_scene: "bank_fee|interest|tax|salary|transfer|other",
  lines: [
    { account_id: "uuid", debit: 0, credit: 100.00, summary: "..." },
    { account_id: "uuid", debit: 100.00, credit: 0, summary: "..." }
  ],
  summary: "银行手续费"
}
Response: { voucher: { id, voucher_no, ... } }
```

## 四、数据模型变更

### payment_entries 表新增

```sql
ALTER TABLE payment_entries
  ADD COLUMN payment_nature VARCHAR(30),           -- 款项性质
  ADD COLUMN voucher_id UUID REFERENCES journal_entries(id);  -- 关联凭证
```

### 新增 payment_nature 枚举（代码层）

| 值 | 中文 | 适用单据 |
|----|------|---------|
| goods_payment | 货款 | 收款/付款 |
| pre_receipt | 预收款 | 收款 |
| pre_payment | 预付款 | 付款 |
| deposit | 保证金 | 收款/付款 |
| reimbursement | 报销款 | 付款 |
| tax | 税款 | 付款 |
| equipment | 设备款 | 付款 |
| rent | 房租 | 付款 |
| advance_repayment | 代垫款归还 | 收款 |
| other | 其他 | 收款/付款 |

```
阶段一 ─── 阶段二 ─── 阶段三 ─── 阶段四
  (P0)       (P0)       (P0)       (P1)

   ├─1.2      ├─2.2      ├─3.2     ├─4.2
   ├─1.3      ├─2.3      ├─3.3     ├─4.3
   ├─1.4      ├─2.4                 ├─4.4
   ├─1.5                             ├─4.5
   ├─1.6
   ├─1.7
   └─1.8
```

- 阶段一和二可并行开发（后端 vs 前端）
- 阶段三依赖阶段一完成
- 阶段四与阶段一二三无强依赖，可并行

## 七、测试策略

- 每个 API 端点需要集成测试覆盖：正常流程 + 异常分支
- 前端需验证：步骤流转正确、数据回显、错误提示
- 核销逻辑测试：一对一核销、多对多核销、部分核销、容差处理
- 凭证生成测试：验证借贷平衡、科目正确、辅助核算正确
