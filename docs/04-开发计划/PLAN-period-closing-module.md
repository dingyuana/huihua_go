## 一、核心刚性约束（最高优先级）

| 约束编号 | 约束描述 |
|---------|---------|
| C001 | 所有系统自动生成的结转凭证，默认固定为【草稿】状态 |
| C002 | 草稿凭证不计入正式账务、不更新科目余额、不参与报表取数、不允许期末结账 |
| C003 | 系统禁止一切自动过账、自动审核、自动确认结转行为，无定时触发、无后台静默执行机制 |
| C004 | 所有结转草稿必须人工逐张审核、人工确认过账，两步人工操作完全分离、不可合并 |
| C005 | 已过账正式结转凭证不可逆，禁止直接删除/修改，调整仅允许红字冲销规范操作 |

## 五、状态流转设计

```
[未执行] → 人工点击生成草稿 → [草稿已生成] → 人工审核/修改/驳回 → [已审核待过账] → 人工确认过账 → [已过账（正式入账）]
```

| 状态码 | 状态名称 | 说明 | 可执行操作 |
|--------|---------|------|-----------|
| `pending` | 未执行 | 结转未开始 | 执行前置检查、触发生成 |
| `draft` | 草稿已生成 | 系统生成草稿，未审核 | 修改、删除、提交审核 |
| `audited` | 已审核待过账 | 审核通过，等待过账 | 过账、驳回 |
| `posted` | 已过账 | 正式入账，不可逆 | 红字冲销 |
| `rejected` | 已驳回 | 审核不通过 | 修改后重新提交 |

## 十、验收标准（可直接用于测试验收）

| 编号 | 验收项 | 验证方法 |
|------|--------|---------|
| A001 | 所有系统生成结转凭证默认草稿 | 检查新生成凭证状态 |
| A002 | 草稿不影响余额、报表、结账 | 修改草稿后查询科目余额 |
| A003 | 无任何自动结转、自动审核、自动过账机制 | 检查定时任务、后台逻辑 |
| A004 | 权限严格互斥，无一人全程包办漏洞 | 用不同角色登录验证 |
| A005 | 流程顺序刚性控制 | 前置异常时尝试后续操作 |
| A006 | 所有操作全程留痕、数据可追溯 | 查询操作日志 |
| A007 | 正式凭证不可直接修改 | 尝试修改已过账凭证 |
| A008 | 异常处理完整，事务原子性一致 | 模拟断电、网络中断场景 |
| A009 | 接口安全合规、参数规范 | 接口测试用例覆盖 |
