# 银行流水驱动全链路数据完整性设计说明书

> 版本：V1.0 | 日期：2026-05-29

---

## 一、设计背景与目标

### 1.1 问题来源

当前系统银行流水→单据→凭证链路存在以下数据完整性缺陷：

| 缺陷 | 现状 | 影响 |
|------|------|------|
| 流水删除无警告 | `delete_transaction_core` 直接删除，无任何关联检查 | 删除已生成单据的流水，导致银企账目孤立 |
| 单据删除不联动 | `delete_receipt/payment/reimbursement` 直接删除，不更新流水状态 | 流水状态仍为 `document_generated`，但关联单据已不存在 |
| 凭证删除不联动 | `delete_voucher` 直接删除，不更新单据状态 | 单据 `voucher_id` 仍存在，但凭证已删除 |
| 操作人信息缺失 | 银行流水和凭证的 `created_by_name` 未记录当前登录人 | 审计追溯不完整 |
| 流水可删已对账 | `is_reconciled=True` 时禁止删除，但强制对账后 `is_reconciled=True` | 已对账流水无法删除（设计如此） |

### 1.2 设计原则

**核心原则：银行流水是数据源头，不可逆操作必须联动上游。**

```
[银行流水] ──CaDocLink(M:N)──> [业务单据] ──(voucher_id)──> [凭证]
     │                              │
     └────── is_reconciled ────────┘
```

1. **流水为起点**：流水生成单据，单据生成凭证。链路顺序不可逆。
2. **下游可删，上游必联**：删除后面的单据/凭证时，必须联动更新前面的数据状态。
3. **禁止孤立删除**：有下游关联的流水，禁止直接删除；必须先处理下游。
4. **操作人可追溯**：所有操作记录操作人身份。
5. **强提醒兜底**：删除操作必须有明确风险提示。

## 二、数据模型完整性约束

### 2.1 实体关系图

```
CaTransaction (银行流水)
  │
  │ 1:N (CaDocLink)
  │    doc_type: receipt | payment | bank_fee | interest | transfer
  │    一个流水可对应多个单据（一对多）
  ▼
BusDocument (业务单据: 6种)
  │
  │ 1:1 (voucher_id)
  │    单据与凭证一一对应
  ▼
AccVoucher (凭证)
```

**多对一（银企对账）**：多张流水可以对应一张单据（如多笔小额流水归集为一笔收款单）。

### 2.2 各实体状态机

#### CaTransaction.status
| 状态 | 含义 | 可跳转 |
|------|------|--------|
| `pending` | 未分类/未生成单据 | → document_generated |
| `document_generated` | 已生成业务单据 | → reconciled |
| `reconciled` | 已银企对账 | — (闭环) |

#### BusDocument.status (收款/付款/报销/银行费用/利息/转账)
| 状态 | 含义 | 可跳转 |
|------|------|--------|
| `draft` | 草稿，未提交 | → pending (提交审核) |
| `pending` | 已提交待审核 | → approved / rejected |
| `approved` | 已审核 | → posted |
| `rejected` | 已驳回 | → draft (重新修改) |
| `posted` | 已过账（凭证已生成） | — (闭环) |

#### AccVoucher.status
| 状态 | 含义 | 可跳转 |
|------|------|--------|
| `draft` | 草稿 | → pending (提交) |
| `pending` | 待审核 | → approved / rejected |
| `approved` | 已审核 | → posted |
| `rejected` | 已驳回 | → draft |
| `posted` | 已过账 | → reversed (红冲) |
| `reversed` | 已冲销 | — (闭环) |

### 2.3 外键与关联字段

| 从 | 到 | 关联字段 | 约束 |
|----|----|---------|------|
| CaDocLink | CaTransaction | `transaction_id` | NOT NULL |
| CaDocLink | BusDocument | `doc_type` + `doc_id` | NOT NULL |
| BusDocument | AccVoucher | `voucher_id` | NULLABLE（未生成凭证时为空） |
| CaCashJournal | CaTransaction | `source_transaction_id` | UNIQUE, NULLABLE |
| AccVoucher | BusDocument | `source_type` + `source_id` | 无外键约束，代码维护 |

## 三、联动规则（核心）

### 3.1 联动规则总表

| 操作 | 影响的上一级 | 联动动作 |
|------|------------|---------|
| 银行流水删除 | CaCashJournal | 检查银企对账状态，已对账禁止删除；未对账：恢复银行账户余额，删除 journal，重新计算后续余额 |
| 业务单据删除 | CaTransaction（经 CaDocLink） | 查找所有关联流水，逐一转为 `pending`（category=None）；删除所有 CaDocLink |
| 凭证删除 | BusDocument（经 voucher_id） | 查找对应单据，清除 `voucher_id` 和 `voucher_no`，单据 status 保持不变（已是 draft/pending） |
| 凭证状态变为 posted | BusDocument | 单据 status → `posted`（由凭证审核/过账流程触发，非本设计范围） |

### 3.2 规则详解

#### R1: 银行流水删除 → 联动 CaDocLink + 流水状态 + CaCashJournal

**触发条件**：`DELETE /api/v1/cash/transactions/{txn_id}`

**前置检查**：
```
IF txn.is_reconciled == True:
    → 拒绝删除，返回："已银企对账的流水不允许直接删除，请先取消对账"

IF EXISTS(CaDocLink WHERE transaction_id = txn_id):
    → 拒绝删除，返回："该流水已关联 {N} 张业务单据（{单据类型列表}），请先删除关联单据"
```

**删除动作**：
1. 查询 `CaCashJournal WHERE source_transaction_id = txn_id`
2. 如果 journal 存在：恢复银行账户余额，删除 journal，调用 `_recalculate_balances`
3. 更新 `CaTransaction SET status = 'pending', category = NULL`
4. 删除所有 `CaDocLink WHERE transaction_id = txn_id`
5. 删除 CaTransaction

**前端行为**：删除按钮点击后，弹出确认对话框，显示"该操作可能影响银企对账平衡"。

#### R2: 业务单据删除 → 联动 CaTransaction + CaDocLink

**触发条件**：`DELETE /api/v1/business/{doc_type}/{doc_id}`

**前置检查**：
```
IF doc.voucher_id IS NOT NULL:
    → 拒绝删除，返回："该单据已生成凭证 {凭证号}，请先删除凭证"
```

**删除动作**：
1. 查询所有 `CaDocLink WHERE doc_type = ? AND doc_id = ?`
2. 对每条 CaDocLink：
   - 找到对应 CaTransaction，更新：`status = 'pending'`, `category = NULL`
   - 同步更新 CaCashJournal 中的 `source_transaction_id`（解除关联）
3. 删除所有查到的 CaDocLink
4. 删除业务单据

#### R3: 凭证删除 → 联动 BusDocument

**触发条件**：`DELETE /api/v1/accounting/vouchers/{voucher_id}`

**凭证删除条件**（已有）：仅 `draft` 或 `rejected` 状态可删除。

**删除动作**：
1. 查询 `AccVoucher WHERE id = voucher_id`，获取 `source_type` 和 `source_id`
2. 如果 `source_type` 匹配业务单据类型（`business_receipt`/`business_payment`/...）：
   - 查询对应业务单据
   - 更新 `doc.voucher_id = NULL`, `doc.voucher_no = NULL`
   - **单据 status 不变**（因为删除的是 draft/rejected 凭证，单据本身可能是 draft 或 pending）
3. 删除 AccVoucher 和 AccVoucherDetail

#### R4: 凭证生成时 → 联动 BusDocument status

**当前行为**（已修复）：生成凭证后，单据 status 保持 `draft`，由人工审核后变为 `posted`。

**不自动过账原则**：自动完成的单据（银行费用/利息/转账）生成的凭证默认 `draft` 状态，需人工审核。

## 四、操作人信息记录

### 4.1 银行流水导入

**修改点**：`POST /api/v1/cash/transactions/import`

当前问题：`engine_classify()` 创建 transaction 时未设置 `created_by`。

**修复**：
```python
transaction = CaTransaction(
    ...
    created_by=current_user.id,
)
# created_by_name 由数据库默认值或服务层填充
```

### 4.2 凭证生成（银行费用/利息/转账）

**修改点**：`generate_bank_fee_voucher` / `generate_interest_income_voucher` / `generate_transfer_voucher`

当前问题：`create_voucher_core` 中 `created_by` 已正确传入，但 `created_by_name` 可能有值也可能为空。

**确认**：检查 `create_voucher_core` 的 `created_by_name` 参数是否正确传递当前用户全名。

### 4.3 单据生成

**修改点**：`auto_generate_documents` 中创建业务单据时

当前问题：6种单据创建时，`created_by_name` 均已正确传入 `current_user.full_name`。

**确认**：已正确实现，无需修改。

## 五、前端强提醒设计

### 5.1 银行流水删除

**场景**：出纳在"待处理流水池"或"已对账流水"中点击删除。

**提醒内容**：
```
⚠️ 删除银行流水 — 银企对账风险提醒

您即将删除流水 [{流水号}]，金额 ¥{金额}，对方：{对方名称}

【风险提示】
该流水已关联 {N} 张业务单据，删除后将导致：
• 银企对账不平衡（银行有记录，企业无记录）
• 关联单据处于孤立状态

【操作确认】
□ 我已知悉上述风险，确认要删除

[取消] [确认删除]
```

### 5.2 业务单据删除

**提醒内容**：
```
⚠️ 删除业务单据 — 流水联动提醒

您即将删除 [{单据类型}] [{单据号}]，金额 ¥{金额}

【影响说明】
• 关联的 {N} 条银行流水将转为"未生成单据"状态
• 银企对账平衡可能受影响

【操作确认】
□ 我已知悉上述影响，确认要删除

[取消] [确认删除]
```

### 5.3 凭证删除

**已有行为**：`DELETE /api/v1/accounting/vouchers/{voucher_id}` 已要求 `confirm=true` + 密码验证 + 删除原因。

**增强**：增加返回信息，告知下游单据状态变化：
```json
{
  "success": true,
  "message": "凭证删除成功",
  "deleted_voucher": { "voucher_no": "...", "source_type": "...", "source_id": "..." },
  "affected_document": {
    "doc_type": "business_receipt",
    "doc_id": "...",
    "previous_voucher_id": "...",
    "doc_status": "draft"
  }
}
```

## 六、状态可逆性矩阵

| 操作 | 可逆？ | 逆向操作 |
|------|--------|---------|
| 流水删除 | ❌ 不可逆 | 需重新导入 |
| 流水生成单据 | ✅ 可逆 | 删除单据，流水恢复 pending |
| 单据删除 | ✅ 可逆（通过联动） | 删除后流水恢复 pending |
| 单据生成凭证 | ✅ 可逆 | 删除凭证，单据 voucher_id 清空 |
| 凭证审核 | ✅ 可逆 | 作废/反审核，凭证恢复 draft |
| 凭证过账 | ✅ 可逆 | 反过账，凭证恢复 approved |
| 银企对账 | ✅ 可逆 | 取消对账标记 |
