## 四、关键设计决策

### 4.1 并发去重：Upsert 而非 ON CONFLICT DO NOTHING

**问题**：原 SPEC 说"DB 报错后重查"，实际上 `ON CONFLICT DO NOTHING` 会静默跳过，导致同一税号发票关联到不同自动创建客户。

**决策**：
```sql
INSERT INTO parties (...)
ON CONFLICT (tax_number) WHERE tenant_id = $2
DO UPDATE SET name = EXCLUDED.name, source = ...
RETURNING id
```

### 4.2 模糊匹配：Preview 阶段返回，用户 Confirm 时指定

**流程**：
```
BatchImportPreview → 返回 CustomerMatchInfo（match_type=fuzzy, fuzzy_score, fuzzy_candidate）
用户预览界面选择"关联已有"或"仍创建"
BatchImportConfirm → 额外传 customer_mappings 参数
```

### 4.3 Audit Trail：轻量方案（表字段）优先

**决策**：在 `ar_invoices` 和 `journal_entries` 上直接加 `approved_by` / `approved_at` 字段，暂不建通用 `audit_logs` 表（复杂查询场景少，当前够用）。

**注**：D-P1.4 全链路追溯需要 `audit_logs` 表，届时再统一设计。

### 4.4 性能要求

- 批量过账 100 张 ≤ 30 秒
- 单张凭证过账 ≤ 200ms
- 单次批量上限 100 张

## 六、可直接补充到总纲文档的内容

无需新增 SPEC，直接在现有文档中补充即可：

1. **`docs/02-需求分析/销售发票导入增强-需求规格说明书-V1.md`** §0 末尾补充：
   ```
   ### 0.1 核心原则补充
   - **人工终审原则**：系统自动生成的应收单、凭证等均为草稿状态，经人工审核过账后才正式生效。
   - **自动拓户原则**：导入发票时，若购方信息在系统中不存在，基于税号自动创建正式客户档案，不中断流程。
   - **税务数据权威原则**：发票号码、金额、税额以导入文件为准，不可在审核中篡改。
   ```

2. **业务流图补充**（在 `销售发票导入增强-需求规格说明书-V1.md` 或新建 `docs/02-需求分析/发票导入全链路流程图.md`）：
   ```
   税务局导出文件 → 导入映射与预校验 →（客户不存在则自动创建）→ 生成发票草稿 → 自动生成应收单草稿 → 自动生成凭证草稿 → 人工审核工作台 → 人工过账/结转 → 正式应收与总账数据 → 进入核销流程
   ```

3. **关键业务规则**（补充到 `需求分析书.md`）：
   ```
   ### 发票导入关键规则
   1. 草稿状态锁定：草稿状态的应收单、凭证，不计入任何账龄分析、信用控制、总账余额。
   2. 红冲规则：已过账的凭证若需更正，必须通过红字冲销，不得直接修改草稿后重新过账。
   3. 凭证过账后状态：docstatus=1（已记账），不可修改。
   4. 批量过账上限：单次批量过账最多100张，超出拆分为多次。
   ```
